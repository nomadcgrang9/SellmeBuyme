# 260305 인공지능 와글와글 자동 답변 시스템 플랜

## 1. 목표

와글와글 커뮤니티에 **자연스러운 AI 답변**을 생성하여 커뮤니티 활성화를 촉진한다.
핵심 원칙: **다른 사용자가 AI 답변임을 인지할 수 없어야 한다.**

---

## 2. 핵심 설계 원칙

### 2.1 안전 제외 규칙 (절대 답변 금지)

AI가 답변하면 **실제 연락/컨택으로 이어질 수 있는** 글은 철저히 제외한다.

| 제외 카테고리 | 키워드/해시태그 | 이유 |
|---|---|---|
| 급구/구인 | `#급구`, `#대타`, `구합니다`, `가능하신 분`, `지원 가능` | 연락 기대 → 허위 응답 위험 |
| 직접 연락 요청 | `쪽지`, `DM`, `연락처`, `전화번호`, `카톡` | 연락 시도 불가 |
| 구직/채용 | `채용`, `합격`, `면접 일정`, `지원서` | 허위 채용 정보 위험 |
| 특정 지역 구인구직 | `OO지역 선생님 계세요?`, `어디 학교` | 실제 매칭 기대 |
| 금전 거래 | `가격`, `시급`, `얼마`, `결제` | 금전 관련 오해 |

### 2.2 답변 허용 카테고리

| 카테고리 | 예시 | AI 역할 |
|---|---|---|
| 고민/걱정 | "기간제 중간 투입 걱정돼요" | 공감 + 경험담 공유 |
| 수업 팁/노하우 | "코딩 커리큘럼 어떻게 짜세요?" | 실용적 조언 |
| 감정 공유 | "합격했습니다!", "떨어졌어요ㅠ" | 축하/위로 |
| 정보 공유 요청 | "재료비 기준이 뭔가요?" | 일반 정보 공유 |
| 업무 범위 고민 | "이것도 강사 업무인가요?" | 경험 기반 의견 |
| 자격/제도 질문 | "비전공인데 지원 가능한가요?" | 일반적 안내 (개인 상황 특정 X) |


## 4. 데이터베이스 설계

### 4.1 `wagle_ai_personas` (AI 가상 유저 풀)

```sql
CREATE TABLE wagle_ai_personas (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  auth_user_id UUID NOT NULL UNIQUE,       -- 실제 Supabase Auth 유저 ID
  display_name TEXT NOT NULL,               -- ex: "따뜻한 솔비", "열정적인 지우"
  profile_image_url TEXT,                   -- 프로필 이미지 URL (선택)
  persona_background JSONB NOT NULL,        -- AI 답변 생성 시 참고할 배경 설정
  -- ex: { "role": "초등 방과후 미술강사", "experience_years": 3, "tone": "다정한" }
  is_active BOOLEAN DEFAULT true,
  last_used_at TIMESTAMPTZ,
  total_replies INTEGER DEFAULT 0,
  created_at TIMESTAMPTZ DEFAULT NOW()
);

-- RLS: 관리자만 접근 가능
ALTER TABLE wagle_ai_personas ENABLE ROW LEVEL SECURITY;
CREATE POLICY "admin_only" ON wagle_ai_personas
  FOR ALL USING (is_admin());
```

### 4.2 `wagle_ai_reply_log` (답변 추적 로그)

```sql
CREATE TABLE wagle_ai_reply_log (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  thread_id UUID NOT NULL REFERENCES wagle_threads(id),
  reply_id UUID REFERENCES wagle_replies(id),       -- 생성된 답변 ID
  persona_id UUID NOT NULL REFERENCES wagle_ai_personas(id),
  classification TEXT NOT NULL,                       -- 'safe' | 'unsafe' | 'skipped'
  classification_reason TEXT,                         -- 분류 사유
  generated_content TEXT,                             -- 생성된 답변 내용
  gemini_model TEXT DEFAULT 'gemini-2.0-flash',
  token_usage JSONB,                                  -- { prompt_tokens, completion_tokens }
  scheduled_at TIMESTAMPTZ,                           -- 예약 발송 시각
  posted_at TIMESTAMPTZ,                              -- 실제 발송 시각
  status TEXT DEFAULT 'pending',                      -- 'pending' | 'posted' | 'cancelled' | 'error'
  error_message TEXT,
  created_at TIMESTAMPTZ DEFAULT NOW()
);

-- RLS: 관리자만 접근 가능
ALTER TABLE wagle_ai_reply_log ENABLE ROW LEVEL SECURITY;
CREATE POLICY "admin_only" ON wagle_ai_reply_log
  FOR ALL USING (is_admin());

-- 인덱스
CREATE INDEX idx_ai_reply_log_thread ON wagle_ai_reply_log(thread_id);
CREATE INDEX idx_ai_reply_log_status ON wagle_ai_reply_log(status);
```

### 5.1 페르소나 풀 (10~15명)

다양한 배경을 가진 가상 인물을 설정하여 답변 다양성을 확보한다.

|---|---|---|---|---|
| 따뜻한 솔비 | 초등 방과후 미술강사 | 3년 | 다정, 이모티콘 사용 | 미술, 돌봄, 유아 |
| 열정적인 지우 | 중등 체육 기간제 | 5년 | 활발, 직설적 | 체육, 기간제, 면접 |
| 꼼꼼한 하율 | 초등 수학 강사 | 2년 | 차분, 정보전달형 | 수학, 교재, 커리큘럼 |
| 씩씩한 도윤 | 코딩 방과후 강사 | 4년 | 친근, 줄임말 사용 | 코딩, IT, 디지털 |
| 밝은 서아 | 영어 방과후 강사 | 3년 | 밝음, 추천 잘함 | 영어, 교재, 파닉스 |

| 유쾌한 나연 | 음악 강사 | 4년 | 유머러스, 공감 | 음악, 악기, 업무범위 |
| 차분한 시현 | 특수교육 보조 | 2년 | 조용, 공감적 | 특수교육, 돌봄 |
| 다정한 은우 | 유치원 방과후 | 3년 | 따뜻, 경험 공유 | 유아, 수업팁 |

### 5.2 페르소나 선택 로직

```
1. 쓰레드 주제(해시태그 + 본문 분석) → 관련 전문 분야 매칭
2. 최근 사용 페르소나 제외 (같은 쓰레드 내 중복 방지)
3. 최근 1시간 내 사용된 페르소나 우선순위 낮춤
4. 랜덤 가중치 적용하여 최종 선택
```

## 6. Edge Function 상세 설계

### 6.1 `wagle-ai-reply/index.ts`

```typescript
// 메인 플로우
async function handleAiReply() {
  // ── STEP 1: 답변 대상 쓰레드 수집 ──
  const candidates = await getUnansweredThreads();
  // - 최근 24시간 내 생성
  // - AI 답변 로그에 없는 쓰레드
  // - reply_count < 3 (이미 활발한 글은 제외)
  // - is_deleted = false

  // ── STEP 2: 콘텐츠 안전 분류 (배치) ──
  const classified = await classifyThreadsBatch(candidates);
  // Gemini에게 각 쓰레드를 'safe' / 'unsafe' 분류 요청
  // unsafe 사유도 함께 기록

  // ── STEP 3: safe 쓰레드만 필터 ──
  const safeThreads = classified.filter(c => c.classification === 'safe');

  // ── STEP 4: 답변 수 제한 (1회 실행당 최대 3~5개) ──
  const selected = pickRandom(safeThreads, MAX_REPLIES_PER_RUN);

  // ── STEP 5: 각 쓰레드별 답변 생성 ──
  for (const thread of selected) {
    const persona = await selectPersona(thread);
    const reply = await generateReply(thread, persona);

    // ── STEP 6: 지연 발송 (즉시 X, 랜덤 딜레이) ──
    const delay = randomDelay(30, 360); // 30분 ~ 6시간
    await scheduleReply(thread, persona, reply, delay);
  }
}
```

### 6.2 콘텐츠 분류 프롬프트

```
당신은 교육 커뮤니티 글의 안전성을 분류하는 시스템입니다.

아래 글이 다음 중 어디에 해당하는지 판단하세요:

[UNSAFE - 답변 금지]
- 특정인을 구하는 글 (강사/교사 구인, 대타 요청)
- 직접 연락을 기대하는 글 (연락처 교환, 쪽지 요청)
- 특정 학교/기관에 대한 구체적 채용 정보
- 금전/시급/보수에 대한 구체적 협상
- 특정 지역 + 특정 시간 조합의 구인구직

[SAFE - 답변 가능]
- 수업 팁/노하우 공유 요청
- 감정 토로 (걱정, 불안, 기쁨, 좌절)
- 일반적 제도/자격 질문
- 업무 범위/강사 생활 고민
- 교재/자료 추천 요청
- 경험담 나눔 요청

응답 형식: { "classification": "safe"|"unsafe", "reason": "..." }
```

### 6.3 답변 생성 프롬프트

```
당신은 "${persona.display_name}" 입니다.
배경: ${persona.persona_background}

아래 커뮤니티 글에 자연스럽게 답변을 달아주세요.

[규칙]
1. 진짜 사람처럼 자연스럽게 (완벽한 문장 X, 구어체 O)
2. 해당 페르소나의 경험에 기반한 답변
3. 너무 길지 않게 (50~150자)
4. 적절히 이모티콘/줄임말 사용 (페르소나 어투에 맞게)
5. 100% 정확하지 않아도 됨 (경험 기반 의견)
6. 절대 연락처, URL, 구체적 기관명 언급 금지
7. "인공지능", "AI", "챗봇" 등의 단어 절대 사용 금지
8. 기존 답변이 있으면 참고하되 중복되지 않는 관점 제시
```

## 7. 발각 방지 전략

### 7.1 타이밍 자연스럽게

```
- 답변 딜레이: 30분 ~ 6시간 (랜덤 분포, 평균 2시간)
- 활동 시간대: 오전 7시 ~ 오후 11시 (새벽 답변 금지)
- 주말/공휴일: 빈도 50% 감소
- 같은 페르소나 연속 사용 금지 (최소 2시간 간격)
```

### 7.2 답변 패턴 다양화

```
- 같은 쓰레드에 2명 이상의 AI가 답변하지 않음
- 전체 쓰레드 중 30~50%만 AI 답변 (전부 답변 X)
- 답변 길이 편차: 30자 ~ 200자
- 간혹 리액션만 남김 (답변 없이 ❤️/🤘만)
- 때로 질문형 답변도 포함 ("저도 궁금해요", "어떤 학년이에요?")
```

### 7.3 페르소나 일관성

```
- 각 페르소나는 자기 전문 분야 위주로만 답변
- 같은 페르소나가 상반된 의견을 내지 않도록 히스토리 참조
- 프로필 이미지: 실제 사람처럼 보이는 아바타 (AI 생성 아바타 서비스 활용)
- 이름 패턴: 기존 샘플 데이터와 동일한 "형용사+이름" 패턴
```

### 7.4 모니터링 & 킬스위치

```
- 관리자 페이지에서 AI 답변 ON/OFF 토글
- 특정 페르소나 비활성화 가능
- AI 답변에 의심 신고가 들어오면 자동 중단
- 일일 최대 답변 수 제한 (하루 10개 이하)
```

## 8. 구현 단계

### Phase 1: 기반 구축 (DB + 페르소나)
1. `wagle_ai_personas`, `wagle_ai_reply_log` 테이블 생성 마이그레이션
2. Supabase Auth에 AI 페르소나 계정 10개 생성 (Admin API)
3. `user_profiles`에 페르소나 프로필 등록
4. 관리자 페이지에 AI 답변 관리 섹션 추가

### Phase 2: 분류 엔진 (Edge Function)
5. `wagle-ai-reply` Edge Function 스캐폴딩
6. 미답변 쓰레드 수집 쿼리 구현
7. Gemini 기반 콘텐츠 안전 분류 로직
8. 분류 결과 로깅

### Phase 3: 답변 생성 엔진
9. 페르소나 선택 알고리즘
10. Gemini 기반 자연스러운 답변 생성
11. 지연 발송 스케줄링 (`scheduled_at` 기반)
12. `service_role` 키로 답변 INSERT (RLS 우회)

### Phase 4: 스케줄링 & 발송
13. 예약된 답변 발송 로직 (별도 Edge Function 또는 pg_cron)
14. 발송 후 `wagle_ai_reply_log.status` 업데이트
15. 에러 핸들링 및 재시도 로직

### Phase 5: 관리 & 모니터링
16. 관리자 페이지: AI 답변 로그 조회
17. 관리자 페이지: 페르소나별 통계
18. 킬스위치 (전체 ON/OFF)
19. 개별 답변 취소/삭제 기능

### Phase 6: 리액션 봇 (선택)
20. 답변 대신 리액션만 남기는 로직 (자연스러움 강화)
21. 리액션 종류/빈도 다양화
