# 260303 와글와글 구현 플랜

## 0. 배경

기존 "채팅" 탭(1:1 DM 기반)을 **와글와글**이라는 교사 커뮤니티 쓰레드 서비스로 전환한다.
학교/기관, 구직자, 강사 구분 없이 누구나 글을 올리고 댓글을 달 수 있는 공개형 소통 공간.

### 기존 채팅 vs 와글와글

| 항목 | 기존 채팅 | 와글와글 |
|------|-----------|----------|
| 성격 | 1:1 비공개 DM | 공개 쓰레드 커뮤니티 |
| 글쓰기 | 상대 지정 필수 | 누구나 자유롭게 작성 |
| 대화 방식 | 실시간 양방향 메시지 | 쓰레드(원글+댓글) 비동기 |
| 노출 범위 | 당사자만 | 전체 공개 (비회원은 미리보기) |
| 용도 | 개인 연락 | 급구/소통/공고보완/정보공유 |

## 1. 요구사항 정리

### 1-1. 핵심 기능

| # | 요구사항 | 상세 |
|---|----------|------|
| 1 | 글쓰기 | 로그인한 누구나 (구인/구직/강사 무관) |
| 2 | 댓글 | 로그인한 누구나 |
| 3 | 열람 | 비회원은 최근 3~5개 미리보기, 로그인 시 전체 |
| 4 | 답글 3단계 | 원글 > 댓글 > 대댓글 > 대대댓글 (Threads 스타일) |
| 5 | 프로필 연동 | 작성자 실명(display_name) + 프로필 이미지 표시 |
| 6 | 해시태그 | 자유 입력, 검색/필터 가능 |
| 7 | 리액션 | 다양한 긍정 리액션 (싫어요 없음) |
| 8 | 알림 | 내 글에 댓글 달리면 알림 |
| 9 | 전국 통합 | 지역 필터 없음, 시간순 정렬 |

### 1-2. 글의 성격 (복합)

- **급구**: "내일 당장 체육 대타 가능하신 분?" (비공식 긴급 요청)
- **소통**: "우리 학교 이런 분 찾아요" + 댓글로 질문/추천/소개
- **정보 공유**: 교사 간 정보/팁 공유

### 1-3. 텍스트 전용

- 이미지/파일 첨부 없음 (MVP)
- 텍스트 + 해시태그만으로 심플하게 운영

## 2. 디자인 원칙 (Anti-Vibe Design 준수)

### 2-1. 절대규칙 체크리스트

```
[x] 이모지 금지 - 아이콘은 Lucide React 컴포넌트만 사용
[x] 글자 뒤 배경색 금지 - 형광펜 스타일 절대 사용하지 않음
[x] 과도한 원색 금지 - 프로젝트 컬러 팔레트만 사용
[x] 바이브코딩 냄새 금지 - 그라디언트/과한 그림자/애니메이션 지양
[x] 컨셉 일관성 - 기존 카드/버튼/모달 패턴 재활용
```

### 2-2. 와글와글 전용 컬러

| 용도 | Tailwind Class | HEX | 비고 |
|------|---------------|-----|------|
| 와글와글 탭 활성 | `text-[#4facfe]` | #4facfe | 기존 채팅 탭 색상 유지 |
| 쓰레드 연결선 | `bg-gray-200` | #E5E7EB | 세로 연결선 |
| 해시태그 텍스트 | `text-blue-600` | #2563EB | 클릭 가능한 태그 |
| 리액션 활성 | `text-[#3B82F6]` | #3B82F6 | 메인 파랑 |
| 미리보기 오버레이 | `bg-gradient-to-t from-white` | - | 비회원 블러 처리 |

### 2-3. 아이콘 선택

현재 "채팅" 탭은 `MessageCircle` (Lucide) 사용 중.
"와글와글"은 여러 사람이 동시에 이야기하는 느낌이므로:

| 후보 | Lucide 아이콘 | 느낌 |
|------|--------------|------|
| **추천** | `MessagesSquare` | 여러 말풍선이 겹친 모양. 다수의 대화가 오가는 느낌 |
| 대안 1 | `MessageSquareMore` | 말풍선 + 점점점. 활발한 대화 |
| 대안 2 | `Users` + `MessageCircle` 조합 | 커스텀 조합 |

> `MessagesSquare`를 1순위로 추천. 와글와글 = 여러 대화가 동시에 일어나는 느낌에 가장 부합.

## 3. 답글 구조 설계 (Threads 스타일 3단계)

### 3-1. X/Threads 조사 결과 반영

- X(트위터): 무한 중첩 시도 후 사용자 반발로 철회. 현재 flat 구조
- Threads(메타): 최대 3단계 제한, 그 이상은 @멘션으로 평탄화
- Instagram: 2단계만 허용
- **업계 결론**: 모바일에서 깊은 중첩은 가로 공간을 잡아먹어 실패

### 3-2. 와글와글 답글 모델

```
depth 0: 원글 (thread)
  depth 1: 댓글 (reply)
    depth 2: 대댓글 (reply to reply)
      depth 3: 대대댓글 (reply to reply to reply)
        depth 3+: @멘션으로 평탄화 (depth 3에 추가)
```

- 시각적 들여쓰기는 depth 0~2까지만 적용 (최대 왼쪽 여백 48px)
- depth 3부터는 depth 2와 같은 레벨에 표시하되 @멘션으로 대상 명시
- 세로 연결선(vertical line)으로 부모-자식 관계 표현
- 댓글 3개 이상 시 "답글 N개 더보기" 접기/펼치기

## 4. 데이터베이스 설계

### 4-1. `wagle_threads` 테이블 (원글)

```sql
CREATE TABLE wagle_threads (
  id            UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  author_id     UUID NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE,
  content       TEXT NOT NULL,
  hashtags      TEXT[] DEFAULT '{}',
  reply_count   INTEGER DEFAULT 0,
  reaction_counts JSONB DEFAULT '{}',
  is_deleted    BOOLEAN DEFAULT FALSE,
  created_at    TIMESTAMPTZ DEFAULT NOW(),
  updated_at    TIMESTAMPTZ DEFAULT NOW()
);

CREATE INDEX idx_wagle_threads_created ON wagle_threads(created_at DESC);
CREATE INDEX idx_wagle_threads_author ON wagle_threads(author_id);
CREATE INDEX idx_wagle_threads_hashtags ON wagle_threads USING GIN(hashtags);
```

### 4-2. `wagle_replies` 테이블 (댓글/대댓글)

```sql
CREATE TABLE wagle_replies (
  id            UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  thread_id     UUID NOT NULL REFERENCES wagle_threads(id) ON DELETE CASCADE,
  parent_id     UUID REFERENCES wagle_replies(id) ON DELETE CASCADE,
  author_id     UUID NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE,
  content       TEXT NOT NULL,
  depth         SMALLINT NOT NULL DEFAULT 1 CHECK (depth BETWEEN 1 AND 3),
  mention_user_id UUID REFERENCES auth.users(id),
  reaction_counts JSONB DEFAULT '{}',
  is_deleted    BOOLEAN DEFAULT FALSE,
  created_at    TIMESTAMPTZ DEFAULT NOW()
);

CREATE INDEX idx_wagle_replies_thread ON wagle_replies(thread_id, created_at);
CREATE INDEX idx_wagle_replies_parent ON wagle_replies(parent_id);
```

### 4-3. `wagle_reactions` 테이블

```sql
CREATE TABLE wagle_reactions (
  id            UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id       UUID NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE,
  target_type   TEXT NOT NULL CHECK (target_type IN ('thread', 'reply')),
  target_id     UUID NOT NULL,
  reaction_type TEXT NOT NULL CHECK (reaction_type IN (
    'like', 'cheer', 'curious', 'thanks'
  )),
  created_at    TIMESTAMPTZ DEFAULT NOW(),
  UNIQUE(user_id, target_type, target_id)
);

CREATE INDEX idx_wagle_reactions_target ON wagle_reactions(target_type, target_id);
```

리액션 종류:
| key | 표시 | 의미 |
|-----|------|------|
| `like` | 하트 아이콘 | 좋아요 |
| `cheer` | 손 흔들기 아이콘 | 응원해요 |
| `curious` | 물음표 아이콘 | 궁금해요 |
| `thanks` | 체크 아이콘 | 감사해요 |

### 4-4. `wagle_notifications` 테이블

```sql
CREATE TABLE wagle_notifications (
  id            UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id       UUID NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE,
  thread_id     UUID NOT NULL REFERENCES wagle_threads(id) ON DELETE CASCADE,
  reply_id      UUID REFERENCES wagle_replies(id) ON DELETE CASCADE,
  actor_id      UUID NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE,
  type          TEXT NOT NULL CHECK (type IN ('reply', 'reaction')),
  is_read       BOOLEAN DEFAULT FALSE,
  created_at    TIMESTAMPTZ DEFAULT NOW()
);

CREATE INDEX idx_wagle_notifications_user ON wagle_notifications(user_id, is_read, created_at DESC);
```

### 4-5. RLS 정책

```sql
-- wagle_threads
ALTER TABLE wagle_threads ENABLE ROW LEVEL SECURITY;

-- 누구나 읽기 (비회원 제한은 프론트에서 처리)
CREATE POLICY "wagle_threads_select" ON wagle_threads
  FOR SELECT USING (true);

-- 로그인 사용자 작성
CREATE POLICY "wagle_threads_insert" ON wagle_threads
  FOR INSERT WITH CHECK (auth.uid() = author_id);

-- 본인 수정
CREATE POLICY "wagle_threads_update" ON wagle_threads
  FOR UPDATE USING (auth.uid() = author_id);

-- wagle_replies (동일 패턴)
-- wagle_reactions (동일 패턴)
-- wagle_notifications (본인 알림만 읽기)
```

## 10. 성능 고려사항

| 항목 | 전략 |
|------|------|
| 피드 페이지네이션 | cursor-based (created_at 기준), 페이지당 15개 |

| 리액션 카운트 | DB 트리거로 reaction_counts JSONB 자동 업데이트 |
| 해시태그 검색 | GIN 인덱스 활용, array @> 연산 |
| Realtime | 새 글/답글 실시간 피드 반영 (Supabase Realtime) |
| 비회원 제한 | 프론트에서 3~5개만 렌더, 나머지 오버레이 |

## 11. 참고

### 현재 UI 구조 (스크린샷 기반 분석)

**모바일 (스크린샷 1):**
- 상단: 학교일자리 로고 + 검색바 + 유저 아이콘
- 필터 칩: 유치원 / 초등담임 / 초등전담 / 교과과목 / 비교과 / 특수 / 방과후·돌봄 / 행정·교육지원 / 기타
- 우측 플로팅: 구직등록(파랑) / 공고등록(초록) / 강사등록(핑크)
- 하단 시트: "주변 목록 N개" + "더보기" 토글
- 하단 네비: 공고보기 / 구직자보기 / 강사보기 / 채팅 / 즐겨찾기

**데스크탑 (스크린샷 2):**
- 좌측 패널 (~250px): 로고, 검색바, 슬로건 배너, 카드 목록
- 중앙: 카카오맵 + 마커
- 우측 사이드바 (LayerToggleBar, ~100px): 로그인 / 구직등록 / 공고등록 / 교원연수강사등록 / 즐겨찾기 / 채팅 / 현재위치로
- 하단: 뷰 토글(공고만/구직자만/교원연수강사만) + 필터 칩
