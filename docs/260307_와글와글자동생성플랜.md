# 260307 와글와글 AI 자동생성 통합 플랜

## 0. 현황 진단

### 0-1. 무엇이 구현되어 있고, 무엇이 작동하지 않는가

| 구분 | 코드 존재 | 실제 작동 | 비고 |
|------|:---------:|:---------:|------|
| Edge Function `wagle-ai-reply` | O | **X** | 배포 안 됨 (deploy workflow에 미등록) |
| DB 테이블 (`wagle_ai_personas`, `wagle_ai_reply_log`, `wagle_ai_config`) | O | **△** | 마이그레이션 SQL 존재, 적용 여부 미확인 |
| AI 페르소나 10명 계정 | O (시드 코드) | **X** | `seed-personas` action 수동 호출 필요하나 미실행 |
| 답변(reply) 자동생성 | O | **X** | 스케줄러(cron) 미설정. 수동 호출해도 페르소나 미생성 상태 |
| 원글(thread) 자동생성 | **X** | **X** | 코드 자체가 없음 (260305 플랜에서 "후속 확장" 언급만) |
| 관리자 페이지 자동생성 버튼 | **X** | **X** | 없음 |
| GitHub Actions 스케줄러 | **X** | **X** | `.github/workflows/`에 와글 관련 워크플로우 없음 |

**결론: AI 답변 시스템은 코드만 존재하고 실제 작동하지 않는 상태. 수동 개입 없이 알아서 돌아가는 것은 아님.**

### 0-2. 현재 와글와글 데이터 상태

- 관리자 콘솔 기준 14개 글 존재 (DB 직접 삽입 또는 수동 작성 추정)
- 프론트엔드에 하드코딩된 데이터는 없음 — 모두 DB(`wagle_threads`)에서 조회
- 날짜가 "3일 전", "4일 전" 등으로 표시 → 더 이상 신선하지 않음

## 1. 목표

### 1-1. 원글(Thread) 자동생성 (신규)

관리자 콘솔에서 버튼 한 번으로 **AI 페르소나 명의의 새 와글 원글 5개를 즉시 생성**하여,
커뮤니티가 활발하게 돌아가는 인상을 사용자에게 준다.

### 1-2. 답변(Reply) 자동생성 (기존 코드 활성화)

이미 작성된 Edge Function 코드를 **실제로 배포하고 스케줄러를 연결**하여,
관리자 개입 없이 자동으로 AI 답변이 달리도록 한다.

## 2. 원글 자동생성 설계

### 2-1. 원글이 답변과 다른 점

| | 답변 자동생성 (기존) | 원글 자동생성 (신규) |
|---|---|---|
| 트리거 | 스케줄러(cron) 자동 | 관리자 버튼 수동 |
| 대상 | 기존 쓰레드에 댓글 달기 | 새로운 쓰레드 자체를 만들기 |
| 안전 분류 | 필요 (구인글에 답변 방지) | **불필요** (AI가 직접 작성하므로 안전한 주제만 생성) |
| 지연(딜레이) | 30~360분 랜덤 | 즉시 INSERT (관리자가 원하는 시점에 생성) |
| RLS | service_role 우회 | service_role 우회 (동일) |
| 페르소나 | 전문분야 매칭 후 선택 | 5명 랜덤 선택, 각자 전문분야에 맞는 글 작성 |

### 2-2. 생성할 글의 카테고리

AI가 생성하는 원글은 **답변 가능한 안전 주제**만 허용:

| 카테고리 | 예시 | 비고 |
|---|---|---|
| 수업 팁/노하우 | "코딩 수업 처음인데 엔트리부터 시작하는 게 맞을까요?" | |
| 교재/자료 추천 | "초등 영어 파닉스 교재 추천해주세요!" | |
| 강사 생활 고민 | "방과후 재료비 기준이 학교마다 다른데 어떻게 하세요?" | |
| 면접/경험 공유 | "기간제 면접 다녀왔는데 분위기 좋았어요" | |
| 업무 범위 질문 | "돌봄교실 강사인데 이것도 제 업무인가요?" | |
| 자격/제도 질문 | "비전공인데 방과후 강사 지원 가능한가요?" | |

**절대 금지 주제** (답변 안전 규칙과 동일):
- 구인/급구/대타 요청 (실제 매칭 기대 유발)
- 연락처/DM/카톡 교환
- 특정 학교/기관명 언급
- 시급/보수 구체적 금액

### 2-3. Gemini 프롬프트 설계

```
당신은 교육 커뮤니티에 글을 작성하는 "${persona.display_name}" 입니다.

교육 현장에서 자연스럽게 나올 법한 커뮤니티 글 1개를 작성하세요.

[절대 규칙]

[출력 형식 — JSON]
```

### 2-5. 자동생성 버튼 동작 플로우

```
[관리자: "자동생성" 클릭]
       ↓
[프론트] supabase.functions.invoke('wagle-ai-reply', {
           body: { action: 'generate-threads', count: 5 }
         })
       ↓
[Edge Function: generate-threads action]
  1. 활성 페르소나 5명 랜덤 선택 (최근 사용 안 한 순)
  2. 기존 최근 글 10개 제목 조회 (주제 중복 방지용)

  4. wagle_threads에 INSERT (author_id = 페르소나의 auth_user_id)
  5. 생성 로그 기록
       ↓
[프론트] 응답 받으면 목록 새로고침
  → "5건 생성 완료" 토스트 표시
```

## 3. 답변 자동생성 활성화 계획

### 3-1. 현재 코드의 2단계 구조 (이미 구현됨, 미작동)

```
[Step 1: generate] ← 2~4시간마다 호출 필요
  - 최근 24시간 미답변 쓰레드 수집
  - 키워드 + Gemini 안전 분류
  - 안전한 글 중 40% 확률로 선별
  - 답변 생성 → wagle_ai_reply_log에 "pending" + scheduled_at 기록
  - 실제 INSERT는 아직 안 함

[Step 2: post-scheduled] ← 30분마다 호출 필요
  - scheduled_at이 지난 pending 로그 조회
  - wagle_replies에 실제 INSERT
  - 로그 상태를 "posted"로 업데이트
```

### 3-2. 왜 자동으로 안 돌아가는가

| 필요한 것 | 현재 상태 | 해결책 |
|-----------|----------|--------|
| Edge Function 배포 | **미배포** (deploy workflow에 미등록) | workflow에 추가 + 배포 |
| GEMINI_API_KEY 시크릿 | **미설정** (추정) | `supabase secrets set GEMINI_API_KEY=...` |
| 페르소나 계정 생성 | **미실행** | `seed-personas` action 1회 호출 |
| 정기 호출 스케줄러 | **없음** | GitHub Actions cron workflow 추가 |

### 3-3. GitHub Actions 스케줄러 설계

```yaml
# .github/workflows/wagle-ai-schedule.yml
name: Wagle AI Auto-Reply Schedule

on:
  schedule:
    # generate: 매 3시간마다 (KST 기준 10시, 13시, 16시, 19시, 22시)
    - cron: '0 1,4,7,10,13 * * *'   # UTC → KST +9
  workflow_dispatch:  # 수동 실행도 가능

jobs:
  generate:
    runs-on: ubuntu-latest
    steps:
      - name: Call generate
        run: |
          curl -X POST "$SUPABASE_URL/functions/v1/wagle-ai-reply" \
            -H "Authorization: Bearer $SERVICE_ROLE_KEY" \
            -H "Content-Type: application/json" \
            -d '{"action": "generate"}'

  post-scheduled:
    runs-on: ubuntu-latest
    steps:
      - name: Call post-scheduled
        run: |
          curl -X POST "$SUPABASE_URL/functions/v1/wagle-ai-reply" \
            -H "Authorization: Bearer $SERVICE_ROLE_KEY" \
            -H "Content-Type: application/json" \
            -d '{"action": "post-scheduled"}'
```

이 워크플로우가 돌면:
- 3시간마다 `generate` → 미답변 글 분석 → 답변 예약
- 같은 시점에 `post-scheduled` → 예약 시각 지난 답변 실제 발송
- **관리자 개입 없이** 자동으로 AI 답변이 달림

### 3-4. 답변 자동생성 안전장치 (이미 코드에 구현됨)

| 장치 | 구현 위치 | 설명 |
|------|----------|------|
| 킬스위치 | `wagle_ai_config.enabled` | false로 바꾸면 즉시 중단 |
| 일일 한도 | `max_replies_per_day: 10` | 하루 최대 10건 |
| 1회 한도 | `max_replies_per_run: 5` | 1번 실행에 최대 5건 |
| 활동 시간 | `active_hours: 7~23` (KST) | 새벽엔 답변 안 함 |
| 확률 필터 | `reply_probability: 0.4` | 안전한 글 중 40%만 답변 |
| 키워드 필터 | `UNSAFE_KEYWORDS` 배열 | 구인/연락/금전 글 1차 차단 |
| Gemini 분류 | 2차 AI 안전 판정 | 키워드 통과해도 AI가 재확인 |
| 랜덤 딜레이 | 30~360분 | 즉시 답변 안 하고 자연스럽게 시차 |
| 페르소나 중복 방지 | 같은 쓰레드 중복 답변 X | reply_log로 체크 |

## 5. Edge Function 수정 상세 — `generate-threads` action

### 5-1. 기존 구조에 추가

```typescript
// wagle-ai-reply/index.ts 의 switch 문에 추가
case 'generate-threads':
  result = await handleGenerateThreads(db, body.count ?? 5);
  break;
```

### 5-2. handleGenerateThreads 핵심 로직

```typescript
async function handleGenerateThreads(db, count: number) {
  // 1. 활성 페르소나 전체 조회 → 랜덤 N명 선택
  const personas = await getRandomPersonas(db, count);

  // 2. 최근 글 10개 조회 (주제 중복 방지)
  const recentThreads = await getRecentThreadContents(db, 10);

  // 3. 각 페르소나별 Gemini 호출
  const results = [];
  for (const persona of personas) {
    const { content, hashtags } = await generateThreadContent(persona, recentThreads);

    // 4. wagle_threads INSERT (service_role로 RLS 우회)
    const { data } = await db.from('wagle_threads').insert({
      author_id: persona.auth_user_id,
      content,
      hashtags,
    }).select('id').single();

    results.push({ persona: persona.display_name, threadId: data.id });
  }

  return { message: `${results.length}건 생성 완료`, threads: results };
}
```

### 5-3. RLS 고려사항

- 기존 RLS: `wagle_threads_insert` → `auth.uid() = author_id`
- Edge Function은 `service_role` 키로 RLS 우회하므로 문제 없음
- 프론트엔드(관리자 콘솔)에서 직접 INSERT하면 RLS에 막힘 → 반드시 Edge Function 경유

## 6. 주의사항 종합

### 6-1. 260305 플랜에서 강조된 사항 (답변 안전 규칙)

- **구인글에 AI가 답변하면 안 됨** — 실제 연락/컨택 기대 유발
- **AI임을 절대 노출 금지** — 발각되면 커뮤니티 신뢰 훼손
- **페르소나 일관성 유지** — 미술 강사가 체육 답변하면 부자연스러움
- **타이밍 자연스럽게** — 새벽 답변 금지, 딜레이 30분~6시간

### 6-2. 원글 생성에서 추가로 조심할 점

| 주의사항 | 이유 |
|----------|------|
| 원글에 구인/급구 내용 생성 금지 | 실제 구인이 아닌 허위 글 → 사용자 혼란 |
| 특정 학교명/지역명 구체적 언급 금지 | 실재하는 곳을 지칭하면 오해 소지 |
| 연락처/카톡 요청 내용 금지 | AI 계정으로 연락 불가 |
| 해시태그에 `급구`, `대타` 사용 금지 | 구인 맥락의 태그는 제외 |
| 같은 페르소나 연속 글쓰기 방지 | `last_used_at` 체크 |
| 기존 글과 주제 중복 방지 | 최근 10개 글을 Gemini에 전달 |
