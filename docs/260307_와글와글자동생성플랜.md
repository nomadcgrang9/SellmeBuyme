# 260307 와글와글 AI 자동생성 통합 플랜

## 0. 현황 진단

### 0-1. 무엇이 구현되어 있고, 무엇이 작동하지 않는가

| 구분 | 코드 존재 | 실제 작동 | 비고 |
|------|:---------:|:---------:|------|
| Edge Function `wagle-ai-reply` | O | **X** | 배포 안 됨 (deploy workflow에 미등록) |
| DB 테이블 (`wagle_ai_personas`, `wagle_ai_reply_log`, `wagle_ai_config`) | O | **△** | 마이그레이션 SQL 존재, 적용 여부 미확인 |
| AI 페르소나 10명 계정 | O (시드 코드) | **X** | `seed-personas` action 수동 호출 필요하나 미실행 |
| 답변(reply) 자동생성 | O | **X** | 스케줄러(cron) 미설정. 수동 호출해도 페르소나 미생성 상태 |
| 원글(thread) 자동생성 | **X** | **X** | 코드 자체가 없음 (260305 플랜에서 "후속 확장" 언급만) |
| 관리자 페이지 자동생성 버튼 | **X** | **X** | 없음 |
| GitHub Actions 스케줄러 | **X** | **X** | `.github/workflows/`에 와글 관련 워크플로우 없음 |

**결론: AI 답변 시스템은 코드만 존재하고 실제 작동하지 않는 상태. 수동 개입 없이 알아서 돌아가는 것은 아님.**

### 0-2. 현재 와글와글 데이터 상태

- 관리자 콘솔 기준 14개 글 존재 (DB 직접 삽입 또는 수동 작성 추정)
- 프론트엔드에 하드코딩된 데이터는 없음 — 모두 DB(`wagle_threads`)에서 조회
- 날짜가 "3일 전", "4일 전" 등으로 표시 → 더 이상 신선하지 않음

## 1. 목표

### 1-1. 원글(Thread) 자동생성 (신규)

관리자 콘솔에서 버튼 한 번으로 **AI 페르소나 명의의 새 와글 원글 5개를 즉시 생성**하여,
커뮤니티가 활발하게 돌아가는 인상을 사용자에게 준다.

### 1-2. 답변(Reply) 자동생성 (기존 코드 활성화)

이미 작성된 Edge Function 코드를 **실제로 배포하고 스케줄러를 연결**하여,
관리자 개입 없이 자동으로 AI 답변이 달리도록 한다.

## 2. 원글 자동생성 설계

### 2-1. 원글이 답변과 다른 점

| | 답변 자동생성 (기존) | 원글 자동생성 (신규) |
|---|---|---|
| 트리거 | 스케줄러(cron) 자동 | 관리자 버튼 수동 |
| 대상 | 기존 쓰레드에 댓글 달기 | 새로운 쓰레드 자체를 만들기 |
| 안전 분류 | 필요 (구인글에 답변 방지) | **불필요** (AI가 직접 작성하므로 안전한 주제만 생성) |
| 지연(딜레이) | 30~360분 랜덤 | 즉시 INSERT (관리자가 원하는 시점에 생성) |
| RLS | service_role 우회 | service_role 우회 (동일) |
| 페르소나 | 전문분야 매칭 후 선택 | 5명 랜덤 선택, 각자 전문분야에 맞는 글 작성 |

### 2-2. 생성할 글의 카테고리

AI가 생성하는 원글은 **답변 가능한 안전 주제**만 허용:

| 카테고리 | 예시 | 비고 |
|---|---|---|
| 수업 팁/노하우 | "코딩 수업 처음인데 엔트리부터 시작하는 게 맞을까요?" | |
| 교재/자료 추천 | "초등 영어 파닉스 교재 추천해주세요!" | |
| 강사 생활 고민 | "방과후 재료비 기준이 학교마다 다른데 어떻게 하세요?" | |
| 면접/경험 공유 | "기간제 면접 다녀왔는데 분위기 좋았어요" | |
| 업무 범위 질문 | "돌봄교실 강사인데 이것도 제 업무인가요?" | |
| 자격/제도 질문 | "비전공인데 방과후 강사 지원 가능한가요?" | |

**절대 금지 주제** (답변 안전 규칙과 동일):
- 구인/급구/대타 요청 (실제 매칭 기대 유발)
- 연락처/DM/카톡 교환
- 특정 학교/기관명 언급
- 시급/보수 구체적 금액

### 2-3. Gemini 프롬프트 설계

```
당신은 교육 커뮤니티에 글을 작성하는 "${persona.display_name}" 입니다.
배경: ${persona.role}, 경력 ${persona.experience_years}년, 어투: ${persona.tone}

교육 현장에서 자연스럽게 나올 법한 커뮤니티 글 1개를 작성하세요.

[주제 카테고리 - 이 중 하나를 자유롭게 선택]
- 수업 운영 팁이나 고민
- 교재/자료 추천 요청
- 강사/교사 생활 경험담
- 업무 범위나 제도에 대한 질문
- 면접/수업 후기

[절대 규칙]
1. 진짜 사람처럼 자연스러운 구어체 (완벽한 문장 X)
2. 당신의 전문분야(${persona.specialties})와 관련된 주제
3. 80~200자 내외
4. 해시태그 2~4개 포함 (본문과 별도로 출력)

8. 이전에 생성된 글과 주제가 겹치지 않게

[출력 형식 — JSON]
{"content": "본문 텍스트", "hashtags": ["태그1", "태그2"]}
```

### 2-4. 관리자 UI — 와글 탭 내 서브탭 구조

기존에는 와글 탭에서 AI 생성 글과 사용자 글이 뒤섞여 구분 불가.
**서브탭 3개로 분리**하여 체계적으로 관리한다.

```
와글 탭
├── [일반 글]      ← 사용자가 직접 작성한 글만 (is_ai_generated = false)
├── [AI 글 관리]   ← AI가 생성한 원글만 (is_ai_generated = true) + 생성 버튼
```

- 기존 와글 탭 안에서 맥락을 유지하면서 관심사 분리

### 2-5. [AI 글 관리] 서브탭 — "AI 글 생성" 버튼 동작 플로우

> 이 버튼은 [AI 글 관리] 서브탭의 필터바 우측에 위치한다 (2-4 목업 참고).

```
[관리자: [AI 글 관리] 서브탭 → "AI 글 생성" 클릭]
       ↓
[프론트] supabase.functions.invoke('wagle-ai-reply', {
           body: { action: 'generate-threads', count: 5 }
         })
       ↓
[Edge Function: generate-threads action]
  1. 활성 페르소나 5명 랜덤 선택 (최근 사용 안 한 순)
  2. 기존 최근 글 10개 제목 조회 (주제 중복 방지용)
  3. 각 페르소나별로 Gemini 호출 → 원글 + 해시태그 생성
  4. wagle_threads에 INSERT:
     - author_id = 페르소나의 auth_user_id
     - is_ai_generated = true        ← NEW
     - ai_persona_id = 페르소나 ID    ← NEW
  5. 생성 로그 기록
       ↓
[프론트] 응답 받으면 [AI 글 관리] 서브탭 목록 새로고침
  → "5건 생성 완료" 토스트 표시
  → 하단 생성 이력에 이번 생성 기록 추가
```

## 3. 답변 자동생성 활성화 계획

### 3-1. 현재 코드의 2단계 구조 (이미 구현됨, 미작동)

```
[Step 1: generate] ← 2~4시간마다 호출 필요
  - 최근 24시간 미답변 쓰레드 수집
  - 키워드 + Gemini 안전 분류
  - 안전한 글 중 40% 확률로 선별
  - 답변 생성 → wagle_ai_reply_log에 "pending" + scheduled_at 기록
  - 실제 INSERT는 아직 안 함

[Step 2: post-scheduled] ← 30분마다 호출 필요
  - scheduled_at이 지난 pending 로그 조회
  - wagle_replies에 실제 INSERT
  - 로그 상태를 "posted"로 업데이트
```

### 3-2. 왜 자동으로 안 돌아가는가

| 필요한 것 | 현재 상태 | 해결책 |
|-----------|----------|--------|
| Edge Function 배포 | **미배포** (deploy workflow에 미등록) | workflow에 추가 + 배포 |
| GEMINI_API_KEY 시크릿 | **미설정** (추정) | `supabase secrets set GEMINI_API_KEY=...` |
| 페르소나 계정 생성 | **미실행** | `seed-personas` action 1회 호출 |
| 정기 호출 스케줄러 | **없음** | GitHub Actions cron workflow 추가 |

### 3-3. GitHub Actions 스케줄러 설계

```yaml
# .github/workflows/wagle-ai-schedule.yml
name: Wagle AI Auto-Reply Schedule

on:
  schedule:
    # generate: 매 3시간마다 (KST 기준 10시, 13시, 16시, 19시, 22시)
    - cron: '0 1,4,7,10,13 * * *'   # UTC → KST +9
  workflow_dispatch:  # 수동 실행도 가능

jobs:
  generate:
    runs-on: ubuntu-latest
    steps:
      - name: Call generate
        run: |
          curl -X POST "$SUPABASE_URL/functions/v1/wagle-ai-reply" \
            -H "Authorization: Bearer $SERVICE_ROLE_KEY" \
            -H "Content-Type: application/json" \
            -d '{"action": "generate"}'

  post-scheduled:
    runs-on: ubuntu-latest
    steps:
      - name: Call post-scheduled
        run: |
          curl -X POST "$SUPABASE_URL/functions/v1/wagle-ai-reply" \
            -H "Authorization: Bearer $SERVICE_ROLE_KEY" \
            -H "Content-Type: application/json" \
            -d '{"action": "post-scheduled"}'
```

이 워크플로우가 돌면:
- 3시간마다 `generate` → 미답변 글 분석 → 답변 예약
- 같은 시점에 `post-scheduled` → 예약 시각 지난 답변 실제 발송
- **관리자 개입 없이** 자동으로 AI 답변이 달림

### 3-4. 답변 자동생성 안전장치 (이미 코드에 구현됨)

| 장치 | 구현 위치 | 설명 |

## 5. Edge Function 수정 상세 — `generate-threads` action

### 5-1. 기존 구조에 추가

```typescript
// wagle-ai-reply/index.ts 의 switch 문에 추가
case 'generate-threads':
  result = await handleGenerateThreads(db, body.count ?? 5);
  break;
```

### 5-2. handleGenerateThreads 핵심 로직

```typescript
async function handleGenerateThreads(db, count: number) {
  // 1. 활성 페르소나 전체 조회 → 랜덤 N명 선택
  const personas = await getRandomPersonas(db, count);

  // 2. 최근 글 10개 조회 (주제 중복 방지)
  const recentThreads = await getRecentThreadContents(db, 10);

  // 3. 각 페르소나별 Gemini 호출
  const results = [];
  for (const persona of personas) {
    const { content, hashtags } = await generateThreadContent(persona, recentThreads);

    // 4. wagle_threads INSERT (service_role로 RLS 우회)
    const { data } = await db.from('wagle_threads').insert({
      author_id: persona.auth_user_id,
      content,
      hashtags,
      is_ai_generated: true,       // AI 식별 플래그
      ai_persona_id: persona.id,   // 페르소나 직접 참조
    }).select('id').single();

    results.push({ persona: persona.display_name, threadId: data.id });
  }

  return { message: `${results.length}건 생성 완료`, threads: results };
}
```

### 5-3. RLS 고려사항

- 기존 RLS: `wagle_threads_insert` → `auth.uid() = author_id`
- Edge Function은 `service_role` 키로 RLS 우회하므로 문제 없음
- 프론트엔드(관리자 콘솔)에서 직접 INSERT하면 RLS에 막힘 → 반드시 Edge Function 경유

## 10. AI 콘텐츠 관리 상세 설계

### 10-1. 설계 배경

**현재 문제:**
- 관리자 콘솔 와글 탭에서 AI가 생성한 글/답변과 실제 사용자가 작성한 글이 뒤섞여 있음
- AI 콘텐츠의 수량, 품질, 페르소나 분포를 파악할 방법이 없음
- AI 답변의 상태(예약/발송/취소/오류)를 확인할 UI가 없음
- AI 설정(킬스위치, 한도 등)을 변경하려면 DB 직접 수정 필요

**해결 방향:**
와글 탭 내 서브탭 3개로 분리하여 일반 글 / AI 글 / AI 답변을 각각 독립적으로 조회·관리한다.

### 10-2. DB 마이그레이션 — `wagle_threads` 확장

AI가 생성한 글을 식별하기 위해 `wagle_threads` 테이블에 컬럼 2개를 추가한다.

**왜 FLAG 방식인가** (JOIN 방식 대비):

| 기준 | FLAG (`is_ai_generated` 컬럼) | JOIN (`wagle_ai_personas` 테이블) |
|------|------|------|
| 쿼리 속도 | `WHERE is_ai_generated = false` 한 줄 | LEFT JOIN + IS NOT NULL 필터 |
| Supabase JS 호환 | `.eq('is_ai_generated', false)` | multi-table filter가 번거로움 |
| 페르소나 참조 | `ai_persona_id`로 직접 참조 | 이중 조회 필요 |
| 프론트 필터링 | `thread.is_ai_generated`로 즉시 분기 | persona auth_user_id 목록을 미리 조회 후 비교 |

```sql
-- 20260307_wagle_ai_thread_flag.sql

ALTER TABLE wagle_threads
  ADD COLUMN is_ai_generated BOOLEAN DEFAULT FALSE,
  ADD COLUMN ai_persona_id UUID REFERENCES wagle_ai_personas(id) ON DELETE SET NULL;

-- AI 글 전용 부분 인덱스
CREATE INDEX idx_wagle_threads_ai ON wagle_threads(is_ai_generated)
  WHERE is_ai_generated = TRUE;

-- 기존 AI 페르소나가 작성한 글 백필 (seed-personas 실행 후에만 유효)
UPDATE wagle_threads t
SET is_ai_generated = TRUE, ai_persona_id = p.id
FROM wagle_ai_personas p
WHERE t.author_id = p.auth_user_id;
```

> **주의:** 페르소나가 아직 시딩되지 않았으면 백필 쿼리는 0건 매칭. Phase 1의 `seed-personas` 실행이 선행 조건.

### 10-3. [일반 글] 서브탭 스펙

**데이터 소스:** `wagle_threads WHERE is_ai_generated = false`

| 항목 | 값 |
|------|---|
| 테이블 컬럼 | 작성자 \| 내용(3cols) \| 해시태그 \| 반응/댓글 \| 상태 \| 관리 |
| 검색 | content, author_name, hashtags (기존과 동일) |
| 상태 필터 | 공개 / 숨김 (기존과 동일) |
| 액션 | 상세보기, 숨기기/공개복구, 완전삭제 (기존과 동일) |
| 카운트 | 서브탭 라벨에 `일반 글 (14)` 형태로 표시 |

**변경 최소화:** 기존 와글 테이블 렌더링 로직 그대로 유지, 쿼리에 `.eq('is_ai_generated', false)` 필터만 추가.

### 10-4. [AI 글 관리] 서브탭 스펙

**데이터 소스:** `wagle_threads WHERE is_ai_generated = true` + `wagle_ai_personas` JOIN (ai_persona_id)

| 항목 | 값 |
|------|---|
| 테이블 컬럼 | **페르소나** \| 내용(2cols) \| 해시태그 \| 반응/댓글 \| 생성일시 \| 상태 \| 관리 |
| 검색 | content, persona_name, hashtags |
| 상태 필터 | 공개 / 숨김 |
| 액션 | 상세보기(페르소나 정보 포함), 숨기기/공개복구, 완전삭제 |
| 카운트 | 서브탭 라벨에 `AI 글 (10)` 형태로 표시 |

**"AI 글 생성" 버튼:**
- 위치: 필터바 우측 (새로고침 버튼 옆)
- 동작: 섹션 2-5 참조
- 로딩: 클릭 시 스피너 표시, 완료 시 토스트 + 목록 새로고침
- 비활성 조건: `isGenerating === true` 동안 disabled

**생성 이력 섹션 (하단):**
- `wagle_ai_thread_log` 또는 `wagle_ai_reply_log`에 `type: 'thread'`로 기록
- 표시 컬럼: 일시 \| 생성 건수 \| 실행자(관리자 이메일)
- 최근 10건만 표시

### 10-5. [AI 답변 관리] 서브탭 스펙

3개 섹션을 세로로 배치한다.

#### (A) AI 설정 패널 (접기/펼치기)

**데이터 소스:** `wagle_ai_config` 테이블 (key-value 구조)

| 설정 항목 | config key | 기본값 | UI 컨트롤 |
|-----------|-----------|--------|----------|
| 킬스위치 | `enabled` | true | ON/OFF 토글 |
| 1회 한도 | `max_replies_per_run` | 5 | 숫자 입력 |
| 일일 한도 | `max_replies_per_day` | 10 | 숫자 입력 |
| 최소 딜레이 | `min_delay_minutes` | 30 | 숫자 입력 (분) |
| 최대 딜레이 | `max_delay_minutes` | 360 | 숫자 입력 (분) |
| 활동 시간 | `active_hours` | {"start":7,"end":23} | 시작/종료 셀렉트 |
| 답변 확률 | `reply_probability` | 0.4 | 슬라이더 또는 숫자 (0~1) |

- "저장" 버튼으로 변경사항 일괄 적용
- 각 key별로 개별 `UPDATE wagle_ai_config SET value = ... WHERE key = ...`
- 킬스위치 OFF 시 빨간 배너: "AI 자동 답변이 비활성화되어 있습니다"

#### (B) 답변 로그 테이블

**데이터 소스:** `wagle_ai_reply_log` JOIN `wagle_ai_personas` (persona_id) JOIN `wagle_threads` (thread_id → 내용 미리보기)

| 컬럼 | 설명 |
|------|------|
| 상태 | 색상 뱃지 — pending(노랑), posted(초록), cancelled(회색), error(빨강) |

| 대상 글 | `wagle_threads.content` 앞 50자 |

| 발송 시각 | `posted_at` (posted만) |
| 관리 | 액션 메뉴 |

**상태 필터:** 전체 / pending / posted / cancelled / error

- `pending` → "취소" (status를 `cancelled`로 변경)
- `posted` → "답변 삭제" (`wagle_replies`에서 DELETE + 로그 status를 `cancelled`로)
- `error` → "사유 보기" (tooltip 또는 모달로 `error_message` 표시)

## 11. AI 원글+답글 묶음 생성 ("대화형 글 생성")

### 11-1. 문제 인식

현재 `generate-threads`는 **원글만 1건** 생성한다.
결과물은 "혼잣말 블로그 포스팅"처럼 보이며, 실제 커뮤니티의 자연스러운 대화 느낌이 전혀 없다.

**좋은 글 (따뜻한 라니아 예시)**:
- 질문형 글 → 다른 페르소나 2명이 답글 → 원글 작성자가 대댓글로 반응
- 글 1 + 답글 2 + 대댓글 1 = **총 4건이 하나의 대화**를 이룸

**나쁜 글 (현실적인 태린 예시)**:
- 일방적 강의 톤, 답글 0개 → 독백 느낌
- 과도한 정보량, 반말+지시형, 해시태그 본문 포함

### 11-2. 개선 목표

`generate-threads` 한 번 호출 시:
```
1건의 "대화 묶음" 생성 = 원글 1건 + 답글 1~3건 + (선택) 대댓글 0~1건
```

여러 페르소나가 한 글에서 자연스럽게 대화하는 구조를 만든다.

### 11-3. 대화 패턴 8종 + 가중치

단일 패턴만 반복하면 금방 티나므로, 8종의 대화 패턴을 가중치 랜덤으로 선택한다.

#### 패턴 목록

**패턴 1: 질문→답변형 (가중치 20%)**
```
A: 고민/질문 (존댓말)
  ├─ B: 경험 기반 답변
  └─ C: 다른 관점 답변
```
예: "방과후 재료비 어떻게 처리하시나요?" → B,C가 각자 경험 공유

**패턴 2: 질문→답변→꼬리질문형 (가중치 10%)**
```
A: 질문
  ├─ B: 답변
  └─ A: @B 꼬리질문 ("그러면 ~은 어떻게 하세요?")
```
예: "수업계획서 양식 있나요?" → B 답변 → A "그러면 학교마다 달라도 그 양식 써도 되나요?"

**패턴 3: 경험공유→공감형 (가중치 20%)**
```
A: 경험담/후기 ("오늘 수업에서 이런 일이 있었는데...")
  ├─ B: 공감 ("저도요ㅋㅋ")
  └─ C: 비슷한 경험 추가
```
예: "오늘 아이들이 너무 안 들어서 진 빠졌어요..." → B,C 공감

**패턴 4: 정보공유→감사형 (가중치 10%)**
```
A: 유용한 정보 공유
  └─ B: "오 몰랐는데 감사합니다!" / 추가 정보 보완
```
예: "에듀넷에서 무료 교안 다운받을 수 있더라고요" → B 감사

**패턴 5: 넋두리→위로형 (가중치 15%)**
```
A: 푸념/고충 토로 ("오늘 진짜 힘들었어요...")
  ├─ B: 위로/공감
  └─ C: 응원 or 비슷한 경험 공유
```
예: "면접 3곳 떨어졌어요ㅠ" → B 위로 → C "저도 처음엔 그랬어요"

**패턴 6: 단독 글 — 답글 없음 (가중치 10%)**
```
A: 짧은 감상/일상 (답글 없음)
```
예: "봄이라 그런지 아이들이 들떠있네요~"
→ 모든 글에 답글이 딱딱 달려 있으면 오히려 기계적으로 보이므로, 답글 없는 글도 섞어야 자연스러움

**패턴 7: 토론형 (가중치 5%)**
```
A: 의견 제시 ("저는 ~라고 생각하는데 다른 분들은요?")
  ├─ B: 동의 + 보충
  └─ C: 살짝 다른 의견 ("저는 오히려 ~가 나았어요")
```
예: "파닉스 먼저 vs 통문자 먼저, 어떻게 생각하세요?"

**패턴 8: 추천요청→추천형 (가중치 10%)**
```
A: "~추천해주세요" / "뭐 쓰세요?"
  ├─ B: 구체적 추천
  └─ C: 다른 추천 or "저도 궁금해요"
```
예: "초등 3학년 미술 교재 추천해주세요" → B,C가 각자 추천

#### 가중치 요약

| 패턴 | 확률 | 참여 인원 | 답글 수 |
|------|------|-----------|---------|
| 1. 질문→답변 | 20% | 3명 | 2 |
| 2. 질문→답변→꼬리질문 | 10% | 2명 | 2 (답글+대댓글) |
| 3. 경험공유→공감 | 20% | 2~3명 | 1~2 |
| 4. 정보공유→감사 | 10% | 2명 | 1 |
| 5. 넋두리→위로 | 15% | 2~3명 | 1~2 |
| 6. 단독 글 (답글 없음) | 10% | 1명 | 0 |
| 7. 토론형 | 5% | 3명 | 2 |
| 8. 추천요청 | 10% | 2~3명 | 1~2 |

**핵심 원칙:**
- 원글 작성자(A)와 답글 작성자(B, C)는 **서로 다른 페르소나**
- 대댓글은 원글 작성자가 답글에 반응하는 형태 (패턴 2에서만 사용)
- `mention_user_id`로 @멘션 관계 표현
- `parent_id`로 대댓글 계층 표현
- 패턴 6(단독 글)이 섞여야 "모든 글에 답글 2개씩" 같은 기계적 느낌 방지

### 11-5. Edge Function 수정 — handleGenerateThreads 개편

#### 패턴 선택 로직 (가중치 랜덤)

```typescript
const PATTERNS = [
  { id: 'question-answer',      weight: 20, personaCount: 3, label: '질문→답변형' },
  { id: 'question-followup',    weight: 10, personaCount: 2, label: '질문→답변→꼬리질문형' },
  { id: 'experience-empathy',   weight: 20, personaCount: 3, label: '경험공유→공감형' },
  { id: 'info-thanks',          weight: 10, personaCount: 2, label: '정보공유→감사형' },
  { id: 'vent-comfort',         weight: 15, personaCount: 3, label: '넋두리→위로형' },
  { id: 'solo',                 weight: 10, personaCount: 1, label: '단독 글 (답글 없음)' },
  { id: 'debate',               weight:  5, personaCount: 3, label: '토론형' },
  { id: 'recommend-request',    weight: 10, personaCount: 3, label: '추천요청→추천형' },
];

function pickPattern(): Pattern {
  const totalWeight = PATTERNS.reduce((sum, p) => sum + p.weight, 0);
  let rand = Math.random() * totalWeight;
  for (const p of PATTERNS) {
    rand -= p.weight;
    if (rand <= 0) return p;
  }
  return PATTERNS[0];
}
```

#### 메인 핸들러

```typescript
    // 1. 패턴 랜덤 선택
    const pattern = pickPattern();

    // 2. 필요한 페르소나 수만큼 선택 (패턴6=1명, 패턴2/4=2명, 나머지=3명)
    const personas = await getRandomPersonas(db, pattern.personaCount);

    // 3. 패턴6(단독 글)이면 답글 없이 원글만 생성
    if (pattern.id === 'solo') {
      const thread = await generateSoloThread(personas[0], recentContents);
      await insertThread(db, personas[0], thread);
      continue;
    }

    // 4. Gemini 1회 호출 → 패턴 정보 포함하여 대화 시나리오 전체 생성
    const scenario = await generateConversation(personas, pattern, recentContents);

    // 5. 원글 INSERT → thread_id 획득
    const threadId = await insertThread(db, personas[0], scenario.thread);

    // 6. 답글들 순차 INSERT (parent_id, mention_user_id 매핑)
    const replyIds = [];
    for (const reply of scenario.replies) {
      const persona = personas[reply.persona_index];
      const parentId = reply.parent_index !== null ? replyIds[reply.parent_index] : null;
      const mentionUserId = reply.mention_persona_index !== undefined
        ? personas[reply.mention_persona_index].auth_user_id
        : null;

      const replyId = await insertReply(db, {
        thread_id: threadId,
        author_id: persona.auth_user_id,
        content: reply.content,
        depth: reply.depth,
        parent_id: parentId,
        mention_user_id: mentionUserId,
      });
      replyIds.push(replyId);
    }

    // 7. reply_count 수동 갱신
    await db.from('wagle_threads')
      .update({ reply_count: scenario.replies.length })
      .eq('id', threadId);
  }
}
```

### 11-10. 페르소나 소진 방지

패턴마다 필요한 페르소나 수가 다르므로 소모량이 가변적:
- 패턴6(단독): 1명, 패턴2/4: 2명, 나머지: 3명
- 3건 생성 시 평균 7~8명 소모 (10명이면 충분)
- `count` 기본값을 5 → **3**으로 변경 권장
- 같은 페르소나가 다른 묶음에서 재사용될 수 있도록, 묶음 간 페르소나 중복은 허용
