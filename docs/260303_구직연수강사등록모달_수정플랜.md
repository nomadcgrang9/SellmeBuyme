## 0. 현재 서비스 아키텍처 (팩트)

### 메인 서비스 = NewLanding (Hero.tsx)

main.tsx에서 기본 경로(`/`)는 **NewLanding**. 레거시 App.tsx는 `/legacy`, `/old` 경로에서만 사용.

### 현재 회원가입 플로우 (NewLanding)

```
구글/카카오 로그인 클릭
  ↓
AuthModal (로그인 선택)
  ↓
Google OAuth → AuthCallback.tsx
  ↓
createMinimalProfile() → user_profiles에 최소 정보 저장 (user_id, email)
  ↓
/ 홈으로 리다이렉트
  ↓
Hero.tsx useEffect → needsTermsAgreement 플래그 확인
  ↓
TermsAgreementModal (약관동의 + 개인정보처리방침 동의만)
  ↓
완료 → 로그인 상태
```

**핵심**: 프로필 3단계 설정(ProfileSetupModal)은 **안 뜸**. 약관동의만 함.

### 현재 프로필 화면

프로필 버튼 클릭 시 → **ProfileModal.tsx** (간단 드롭다운)
- 이메일 표시
- "로그인됨" 텍스트
- "내 마커 관리" 링크
- "로그아웃" 버튼
- **프로필 수정 기능 없음** ← 스크린샷에서 확인됨

### 구직 등록 플로우 (미로그인 상태에서)

```
"구직등록" 버튼 클릭 (미로그인)
  ↓
pendingAction = 'register' 설정
  ↓

  ↓

  ↓
약관동의 완료 → pendingAction 감지

  ↓
구직 등록 폼 작성 → teacher_markers에 저장 → 마커 생성
```

## 1. 핵심 질문에 대한 분석

### Q1. 회원정보 수정이 필요한가?

**현재 상태**:
- NewLanding에는 프로필 수정 기능이 **아예 없음**
- ProfileModal에 "로그아웃"만 있고 "수정" 없음
- user_profiles에 저장되는 정보: user_id, email, display_name(자동생성), agree_terms

**분석**:
- 우리 서비스는 개인정보를 최소 수집하는 구조
- 이메일은 OAuth에서 자동으로 가져옴
- 구직 등록 시 필요한 정보(닉네임, 분야, 연락처 등)는 **TeacherMarkerModal에서 직접 입력**
- 따라서 별도 "회원정보 수정" 페이지는 **불필요**

**다만 필요할 수 있는 것**:
- 등록한 마커 수정/삭제 (현재 "내 마커 관리" 링크로 존재)
- 회원 탈퇴 (WithdrawalModal — 레거시에만 연결됨)

### Q2. 구직등록에서 알아서 등록되는 건데?

**맞다.** 현재 구조:

| 데이터 | 수집 시점 | 저장 위치 |
|--------|----------|----------|
| 이메일 | OAuth 자동 | user_profiles |
| 약관동의 | TermsAgreementModal | user_profiles |
| 닉네임, 분야, 과목, 경력, 지역, 전화번호, 자기소개 | TeacherMarkerModal | teacher_markers |

회원가입(user_profiles)에서 수집하는 건 이메일+약관뿐이고, 실질적인 프로필 정보는 **구직 등록 시 teacher_markers에 저장**된다.

### Q3. 회원가입 과정에서 구직 모달처럼 넣으면 자동 마커 생성 가능?

**아이디어 분석**:

```
현재: 가입 → 약관동의 → (끝) → 별도로 구직등록 클릭 → 마커 생성
제안: 가입 → 약관동의 → 구직/강사 등록 폼 → 마커 자동 생성
```

**장점**:
- 가입 = 등록이므로 이탈 줄어듦 (가입했는데 등록 안 하는 사용자 방지)
- 마커 수 증가 → 서비스 활성도 증가
- 사용자 입장에서 한 번에 끝남

**단점/고려사항**:
- 구직이 아닌 사용자도 있음 (학교 담당자가 공고만 보려고 가입하는 경우)
- 강제로 구직 등록 폼을 보여주면 "나는 구직자가 아닌데?" 이탈 가능
- 현재도 "구직등록" 버튼 → 미로그인 → 자동 로그인 → 자동 구직모달 오픈이 **이미 seamless하게 동작 중**

**결론**: 현재 `pendingAction` 시스템이 이미 "가입 → 즉시 등록" 플로우를 지원하고 있다. 사용자가 "구직등록" 버튼을 누른 채로 가입하면 가입 완료 후 자동으로 구직 모달이 열린다. 다만 **약관동의 후 "무엇을 등록할지" 선택지를 보여주는 방식**은 검토할 만하다.

## 2. 레거시 코드 정리 방향

### ProfileSetupModal 관련 파일들의 상태

| 파일 | 현재 상태 | 방향 |
|------|----------|------|
| `ProfileSetupModal.tsx` | 레거시 App에서만 사용 | 당장 삭제 불필요, 추후 레거시 App 제거 시 함께 삭제 |
| `ProfileStep2Field.tsx` | 이전 세션에서 수정됨, 레거시 전용 | AI 추천 영향도 QA 후 판단 |
| `ProfileViewModal.tsx` | 레거시 App에서만 사용 | 동일 |
| `ProfileStep1Basic.tsx` | 레거시 전용 | 동일 |
| `ProfileStep1Role.tsx` | 레거시 전용 | 동일 |
| `ProfileStep3Location.tsx` | 레거시 전용 | 동일 |

### AI 추천(capable_subjects) 영향

**중요**: ProfileSetupModal에서 수집하는 `capable_subjects`는 AI 추천 Edge Function에서 사용됨.
그러나 NewLanding 플로우에서는 ProfileSetupModal이 **안 뜨므로** `capable_subjects`가 **비어있는 상태**로 남음.

이는 곧:
- NewLanding으로 가입한 사용자는 AI 추천의 과목 매칭 점수가 **0점** (capable_subjects 없음)
- AI 추천이 지역/역할 기반으로만 작동하게 됨
- **이전 세션의 ProfileStep2Field 수정은 NewLanding 사용자에게 영향 없음**

## 3. 구직 등록 모달 카테고리 불일치 수정

### 수정 대상: `types/markers.ts`

#### A. 교과과목 2차 분류

Before:
```
['국어', '영어', '수학', '과학', '사회', '체육', '음악', '미술', '정보', '기술가정', '기타']
```

After:
```
['국어', '영어', '수학', '과학', '사회', '역사', '도덕·윤리', '체육', '음악', '미술', '기술·가정', '정보', '중국어', '일본어', '한문', '기타']
```

변경 사항:
- `역사` 추가 (사회와 분리)
- `도덕·윤리` 추가
- `기술가정` → `기술·가정` (네이밍 통일, 정보와 분리 유지)
- `중국어`, `일본어`, `한문` 개별 추가
- `프랑스어`, `스페인어` 미추가 (공고 빈도 극히 낮음)

#### B. 1차 분류

| 항목 | 결정 | 사유 |
|------|------|------|
| 초등전담 추가 | **안 함** | 사용자 확인: 불필요 |
| 특수교육→특수 | **변경** | 필터와 네이밍 통일 |
