# 260303 교원연수강사 등록 개선 플랜

## 0. 배경

구직자(Teacher) 등록 시스템을 전면 개편한 바 있음 (260303_구직카드개선플랜.md 참고).
- 2단계 분류(1차+2차) 도입, 메인뱃지 로직 변경
- 구직중/구직종료 상태칩 + 토글 추가
- 카드 리스트 UI 정비 (좌측바 통일, 정보행 재배치)
- 상세패널 개선 (길찾기/이메일 버튼 삭제 → 정보행 전환)

**이번 플랜**: 같은 맥락에서 교원연수강사(Instructor) 등록 시스템을 점검하고, 구직자와의 일관성은 맞추되 강사 고유의 차별점은 유지하는 방향으로 개선.

## 1. 현재 실태 분석

### 1-1. 등록 모달 (`InstructorMarkerModal.tsx`)

**현재 입력 필드:**

| # | 필드 | 필수 | 현재 UI |
|---|------|------|---------|
| 1 | 희망 활동 위치 | * | `RegionSearchInput` 컴포넌트 |
| 2 | 이름/닉네임 | * | 텍스트 + 랜덤 생성 버튼 |
| 3 | 이메일 | * | 텍스트 (Google 계정 자동 입력) |
| 4 | 전화번호 | 선택 | 텍스트 + phone_public 체크 |
| 5 | 전문분야 | * | 20개 버튼 복수 선택 + 기타 입력 |
| 6 | 연수 대상 | * | 4개 체크박스 (교원/학부모/교직원/기타) |
| 7 | 활동 가능 지역 | * | 지역 버튼 복수 선택 |
| 8 | 경력 | 선택 | EXPERIENCE_OPTIONS 버튼 |
| 9 | 활동내용 | 선택 | textarea (1000자) |
| 10 | 프로필 이미지 | 선택 | 파일 업로드 + 드래그앤드롭 |
| 11 | 개인정보 동의 | * | 체크박스 |

**문제점:**
- 전문분야 20개가 한 화면에 나열 → 선택 부담이 큼
- 전문분야 분류 체계가 평면(1단계)이어서 구직자(2단계)와 구조적 불일치
- "수정" 기능 없음 → 등록 후 정보 변경 불가
- 활동내용 입력 가이드 부족

### 1-2. 카드 리스트 (`Hero.tsx` 3122~3203행)

**현재 구조:**
```
├───────────────────────────────────┤  강사 카드 (현재)
│  (📷) 홍길동                       │  ← 좌측바 없음
│       [연수강사]                   │  ← 핑크 뱃지 (고정)
│       에듀테크/AI, 생활지도/상담    │  ← 전문분야 텍스트 나열
│       서울, 경기                    │  ← 활동지역
├───────────────────────────────────┤
```

**문제점:**
1. **좌측 색상바 없음** → 구직자 카드는 하늘색 좌측바가 있는데, 강사 카드는 `border-l-transparent`
2. **상태칩 없음** → 구직자는 "구직중/구직종료" 칩이 있지만, 강사는 상태 표시 없음
3. **뱃지가 "연수강사" 고정** → 전문분야가 뱃지로 표시되지 않음 (텍스트 나열)
4. **정보량 부족** → 경력, 연수대상 등 미표시
5. **hover 효과 단순** → `hover:bg-pink-50/50`만 있고, 선택 시 좌측바 색상 변화 없음
6. **선택 상태 구분 부족** → 구직자는 `selectedTeacher?.id === marker.id` 시 `bg-sky-50/50` + 좌측바 표시되지만, 강사는 선택 상태 구분이 약함

### 1-3. 상세패널 (`InstructorDetailPanel.tsx`)

**현재 구조:**
```
┌─────────────────────────────────┐
│  강사 정보                   ✕  │  ← 핑크 헤더
│─────────────────────────────────│
│  (📷)  홍길동                   │
│         경력 3년                │
│─────────────────────────────────│
│  💡 전문분야                    │
│  👥 연수대상                    │
│  📍 활동 가능 지역              │
│  📄 활동이력                    │
│  📞 연락처 (로그인 시)          │
│─────────────────────────────────│
│  [길찾기]  [이메일]             │  ← 하단 버튼
└─────────────────────────────────┘
```

**문제점:**
1. **길찾기 버튼 불필요** → 구직자 상세패널에서 삭제한 것처럼, 강사에게 길찾기는 의미 없음 (강사가 방문하는 것이 아님)
2. **이메일 버튼 → 정보행 전환 필요** → 구직자와 동일하게 정보행으로 변경
3. **전문분야 표시 방식** → 콤마 나열이어서 시각적 구분 약함
4. **상태 토글 없음** → 강사도 활동중/비활성 상태 관리 필요
5. **이메일 복사 기능 없음** → 구직자 상세패널에는 복사 버튼 있음

### 1-4. 마커 팝업 (`MarkerPopup.tsx`)

**현재 instructor 영역:**
```tsx
// 전문분야 최대 3개 핑크 pill로 표시
specialties.slice(0, 3).map(...)  // bg-pink-50 text-pink-700

// 상태칩 없음 (teacher만 구직중/종료 표시)
// 상태 토글 없음 (teacher만 본인 토글 가능)
```

**문제점:**
1. **상태칩/토글 미구현** → teacher는 구직중/종료 칩 + 본인 토글 있으나 instructor는 없음
2. **전문분야 3개 제한** → 나머지 전문분야를 볼 수 없음
3. **연수대상 미표시** → 교원/학부모 구분이 팝업에서 보이지 않음

#### 1-5-3. 모바일 바텀시트 (`MobileBottomSheet.tsx`)

**현재 구조:**
```
[collapsed] → 하단 플로팅 바 "주변 목록 N개" + "더보기"
```

#### 1-5-4. 마커 팝업 모바일 동작 (`MarkerPopup.tsx`)

**구직자 마커 팝업 (개선 완료):**
- 상태칩: `●구직중`/`○구직종료` 표시
- 본인 마커: 토글 스위치로 상태 변경 가능
- 뱃지: sub[0] 메인 + primary 보조 (컬러pill)
- 나머지 sub[1:] 회색 pill로 추가 표시
- 학교급/활동지역/자기소개 표시

**강사 마커 팝업 (현재):**
- 상태칩: **없음**
- 본인 마커: 토글 **없음**
- 뱃지: specialties[0:3] 핑크 pill (최대 3개, +N 카운트 없음)
- 연수대상: 표시됨 (회색 pill)
- 활동지역: 표시됨
- 활동이력: 표시됨

#### 1-5-5. 등록 모달 모바일 사용성 비교

**두 모달 공통 구조:**
```
[헤더] 글래스모피즘 (스카이블루 그라데이션)
[본문] flex-1 overflow-y-auto (스크롤)
[푸터] 등록하기 버튼 (고정)
max-h: 90vh, max-w: lg (max-w-lg)
```

| 항목 | 구직자 등록 | 강사 등록 | 차이 |
|------|-----------|----------|------|
| **닉네임 라벨** | "닉네임" | "이름/닉네임" | 강사는 실명 가능 |
| **분류 선택** | 1차(8개, 단일) → 2차(동적, 복수) | 전문분야(20개, 복수) | 구조 다름 |
| **분류 UI** | 1차 선택 후 2차 자동 표시 | 20개 한 번에 나열 | **강사 20개 과다** |
| **학교급** | 교과과목일 때만 표시 | 없음 (연수대상으로 대체) | OK |
| **활동 가능 지역** | 선택 (복수) | 필수* (복수) | 강사가 더 엄격 |
| **소개/이력** | "자기소개" (500자) | "활동내용" (1000자) | 강사가 더 상세 |
| **개인정보 동의** | "실제 구인구직이 되기 위한..." 안내문 | "학교와 사람을 연결하기..." 안내문 | 약간 다름 |
| **수정 기능** | 없음 | 없음 | 둘 다 미구현 |

### 1-6. 데이터 모델 (`instructorMarkers.ts`)

**현재 구조:**
```typescript
interface InstructorMarker {
  specialties: InstructorSpecialty[];  // 20개 전문분야 (평면 배열)
  custom_specialty?: string;           // 기타 1개
  target_audience: TargetAudience[];   // 교원/학부모/교직원/기타
  activity_history?: string;           // 활동이력
  is_active: boolean;                  // DB에 존재하지만 UI 미사용
  // ... 기타 공통 필드
}
```

**핵심 이슈:**
- `is_active` 필드가 DB에 있으나 UI에서 전혀 활용되지 않음
- 전문분야가 평면 구조(1단계) → 구직자의 2단계 분류와 불일치

### 2-1. 동일하게 적용할 패턴 (일관성)

### 2-2. 강사만의 차별점 (유지/강화)

| # | 항목 | 구직자 | 강사 | 이유 |
|---|------|-------|------|------|
| 1 | **분류 체계** | 2단계 (1차 8개 → 2차 N개) | 1단계 유지 (20개 직접 선택) | 강사 전문분야는 교차 조합이 많아 계층 분류가 부자연스러움 |

| 7 | **상태 라벨** | "구직중/구직종료" | "활동중/활동종료" | 강사는 "구직"이 아닌 "활동" 개념 |

```tsx
onClick={async () => {
  if (isToggling) return;
  setIsToggling(true);
  const newStatus = !localIsActive;
  try {
    await toggleInstructorMarkerStatus(instructor.id, newStatus);
    setLocalIsActive(newStatus);
    instructor.is_active = newStatus;
  } catch (err) { ... }
  finally { setIsToggling(false); }
}}
```

```typescript
export async function toggleInstructorMarkerStatus(markerId: string, isActive: boolean) {
  const { error } = await supabase
    .from('instructor_markers')
    .update({ is_active: isActive, updated_at: new Date().toISOString() })
    .eq('id', markerId)
    .eq('user_id', (await supabase.auth.getUser()).data.user?.id);

  if (error) throw error;
}
```
