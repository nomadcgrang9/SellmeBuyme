## 1. DB 연동 쿼리 (Supabase SQL 에디터에서 직접 실행)

### 1-1. 테이블 생성 (복붙용)

```sql
CREATE TABLE IF NOT EXISTS public.bookmarks (
  id          uuid DEFAULT gen_random_uuid() PRIMARY KEY,
  user_id     uuid NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE,
  card_id     uuid NOT NULL,
  card_type   text NOT NULL CHECK (card_type IN ('job', 'talent', 'experience')),
  created_at  timestamptz DEFAULT now() NOT NULL,
  UNIQUE(user_id, card_id, card_type)
);
```

### 1-2. 인덱스 생성 (복붙용)

```sql
CREATE INDEX IF NOT EXISTS idx_bookmarks_user_id 
  ON public.bookmarks(user_id);

CREATE INDEX IF NOT EXISTS idx_bookmarks_user_card_type 
  ON public.bookmarks(user_id, card_type);

CREATE INDEX IF NOT EXISTS idx_bookmarks_created_at 
  ON public.bookmarks(created_at DESC);
```

### 1-3. RLS 정책 설정 (복붙용)

```sql
ALTER TABLE public.bookmarks ENABLE ROW LEVEL SECURITY;

CREATE POLICY "Users can view own bookmarks"
  ON public.bookmarks FOR SELECT
  USING (auth.uid() = user_id);

CREATE POLICY "Users can insert own bookmarks"
  ON public.bookmarks FOR INSERT
  WITH CHECK (auth.uid() = user_id);

CREATE POLICY "Users can delete own bookmarks"
  ON public.bookmarks FOR DELETE
  USING (auth.uid() = user_id);
```

### 1-4. 생성 확인용 쿼리 (복붙용)

```sql
SELECT table_name, row_security 
FROM information_schema.tables 
WHERE table_name = 'bookmarks';

SELECT * FROM pg_policies WHERE tablename = 'bookmarks';
```

### 시나리오 A: 공고 카드에서 즐겨찾기 추가 후 즐겨찾기 패널 확인

```
1. 사용자, 좌측 공고 카드 목록 확인
2. 관심있는 공고 카드의 🤍 하트 아이콘 클릭
   → 즉시 ❤️ 빨간 하트로 전환 (Optimistic UI)
   → DB INSERT INTO bookmarks
   → "북마크했습니다" 토스트 메시지
3. 우측 사이드바 LayerToggleBar의 ⭐ 즐겨찾기 클릭
4. 즐겨찾기 사이드 패널 슬라이드-인 (우측에서)
5. 방금 추가한 공고가 리스트 상단에 표시
6. 패널 내 카드 클릭 → 상세 패널 열림 (기존 동작)
7. 패널 내 ❤️ 클릭 → 즐겨찾기 해제, 목록에서 사라짐
```

> **요구사항**: 즐겨찾기 창의 카드들은 높이가 각각 다르므로 고정 높이를 주고,  
> 안이 짧으면 OK, 길어지는 것은 고정높이 안에서 스크롤.

### 7-1. 타입별 고정 높이 제안

| 카드 타입 | 고정 높이 | 근거 |
|----------|----------|------|
| 공고 (job) | `120px` | 기관명 + 제목 + 위치/급여 + 마감 |
| 구직 (talent) | `120px` | 이름 + 전문분야 + 위치/경력 + 액션 |
| 강사 (experience) | `130px` | 제목 + 소개 + 지역 + 액션 (소개가 길 수 있음) |

### 7-2. 구현 패턴

```tsx
// FavoriteCard.tsx 스타일 예시
<div
  className="relative bg-white border border-gray-200 rounded-lg overflow-hidden"
  style={{ height: '120px' }}  // ← 고정 높이
>
  {/* 상단 고정: 타입뱃지 + D-day */}
  <div className="flex justify-between px-3 pt-2 pb-1 flex-shrink-0">
    <span>공고</span>
    <span>D-3</span>
  </div>

  {/* 중간 스크롤 영역 */}
  <div
    className="overflow-y-auto px-3"
    style={{ height: 'calc(120px - 24px - 32px)' }}  // 전체 - 상단 - 하단
  >
    <h4>성남교육지원청</h4>
    <p>방과후강사 모집 (아주 긴 내용이 여기에 들어갈 경우 스크롤)</p>
    <p>📍 경기 성남</p>
  </div>

  {/* 하단 고정: 액션 버튼 */}
  <div className="absolute bottom-0 left-0 right-0 flex justify-end px-3 pb-2 bg-white border-t border-gray-50">
    <button onClick={handleRemoveBookmark}>
      <IconHeart fill="currentColor" className="text-red-500" />
      <span>해제</span>
    </button>
  </div>
</div>
```

### Q2. 로그인 직후 자동 북마크 로드 — 쉬운 설명

> ✅ **컨펌: 자동 로드로 결정**

**현재 상황 (문제):**
앱에서 하트를 누르면 즉시 빨간 하트로 바뀌는데,  
이것은 **브라우저 메모리(Store)**에만 저장됩니다.  
새로고침하면 Store가 초기화되기 때문에 하트가 다시 회색으로 보입니다.

**"로그인 직후 자동 로드"란?**
```
사용자 로그인 성공
    ↓
서버(Supabase)에서 "이 사용자가 북마크한 카드 ID 목록" 조회
    ↓  
bookmarkStore에 저장
    ↓
카드들이 처음부터 정확하게 ❤️ 빨간 하트로 표시됨
```

**현재 코드에서 이미 함수는 있지만 연결이 끊겨 있음:**
- `fetchUserBookmarkIds()` — DB에서 ID 조회 ✅ 있음
- `bookmarkStore.loadBookmarks()` — Store에 저장 ✅ 있음  
- **authStore 로그인 성공 후 위 두 함수 호출** ← ❌ 연결 안 됨 (이게 지금 문제)

### Q8. 마감/삭제된 공고의 즐겨찾기 유지 — 기술적 검토

> ✅ **컨펌: 즐겨찾기에 그대로 유지**

**질문: 날짜 지난 공고가 지도/리스트에는 안 보이는데 북마크 창에서는 유지 가능한가?**

#### 케이스 A: "기간 마감" 공고 (DB에 데이터는 있음)
```
현재 코드 분석 (queries.ts L4568~4571):  
supabase.from('job_postings').select('*').in('id', jobIds)
→ 아무 필터 없음 → deadline 지나도 데이터 있으면 그대로 조회됨
```
**→ ✅ 가능. 지도/리스트에서는 마감공고를 필터링하지만, 즐겨찾기 조회는 필터 없이 id로만 조회하기 때문에 그대로 표시됨.**

#### 케이스 B: "DB에서 완전히 삭제된" 공고 (크롤러가 삭제 또는 관리자가 삭제)
```
supabase.from('job_postings').select('*').in('id', jobIds)
→ 해당 id를 못 찾음 → 조회 결과에서 빠짐
→ 즐겨찾기 목록에도 표시 안 됨
```
**→ ⚠️ 불가. DB에서 지워지면 즐겨찾기에서도 사라짐.**  
(단, bookmarks 테이블의 북마크 레코드 자체는 남아있음 — 고아 데이터)

#### 결론 및 대응 전략
- **마감된 공고** → ✅ 그대로 표시 (사용자가 날짜 보고 판단)
- **DB 삭제된 공고** → 어쩔 수 없이 사라짐, 자연스러운 동작으로 수용
- **추가 처리 선택사항**: 즐겨찾기 패널에서 카드를 찾지 못하면 `bookmarks` 테이블에서도 해당 레코드 정리(가비지 컬렉션) 가능 → **나중에 고도화 시 선택사항**
