### 1.2 기존 DB 테이블 (Supabase에 존재)

**3개 마이그레이션 적용 완료:**
- `20250113_chat_system.sql` - 기본 스키마
- `20251114_fix_chat_participants_rls.sql` - RLS 수정
- `20251115_fix_chat_participants_rls_final.sql` - RLS 최종 수정

**테이블:**

```sql
-- chat_rooms (1:1 채팅방)
id UUID PK
participant_1_id UUID FK -> auth.users
participant_2_id UUID FK -> auth.users
context_type TEXT ('talent' | 'experience')
context_card_id UUID
last_message_at TIMESTAMPTZ
is_archived BOOLEAN
UNIQUE(participant_1_id, participant_2_id, context_card_id)

-- chat_messages (메시지)
id UUID PK
room_id UUID FK -> chat_rooms
sender_id UUID FK -> auth.users
content TEXT
message_type TEXT ('text' | 'system' | 'file')
file_url, file_name TEXT
file_size INTEGER, file_type TEXT
is_read BOOLEAN, read_at TIMESTAMPTZ

-- chat_participants (참여자)
id UUID PK
room_id UUID FK -> chat_rooms
user_id UUID FK -> auth.users
last_read_message_id UUID FK -> chat_messages
last_read_at TIMESTAMPTZ
unread_count INTEGER
```

**DB 함수:**
- `get_or_create_chat_room(user1, user2, ctx_type, ctx_card_id)` - 채팅방 생성/조회
- `mark_room_as_read(room_id, user_id)` - 읽음 처리

**트리거:**
- `trigger_update_last_message` - 메시지 INSERT 시 `chat_rooms.last_message_at` 갱신
- `trigger_increment_unread` - 메시지 INSERT 시 수신자 `unread_count` 증가

**Realtime 발행:**
- `chat_messages`, `chat_rooms`, `chat_participants` 모두 `supabase_realtime` publication에 등록됨

### 1.4 와글와글과의 차이점 (핵심)

| 항목 | 와글와글 (커뮤니티) | 1:1 채팅 |
|------|-------------------|---------|
| 성격 | 공개 게시판/포럼 | 비공개 1:1 대화 |
| 데이터 구조 | Thread -> Reply (트리) | Room -> Message (플랫) |
| 참여자 | 누구나 글 읽기/쓰기 | 2명만 참여 |
| 시작 방식 | FAB으로 새 글 작성 | 특정 사용자 타겟 지정 |
| 알림 | 내 글에 댓글 달림 | 상대방이 메시지 보냄 |
| 읽음 처리 | 없음 | 메시지별 읽음 확인 |
| 파일 첨부 | 없음 | 20MB 이하 모든 파일 |

## 2. DB 스키마 (추가 마이그레이션)

기존 테이블을 재활용하되, 아래 마이그레이션을 추가 실행합니다.

### 2.1 Supabase SQL 에디터에서 실행할 쿼리

```sql
-- =====================================================
-- 260304 채팅 시스템 개선 마이그레이션
-- 기존 chat_rooms, chat_messages, chat_participants 재활용
-- =====================================================

-- 1) chat_rooms에 display 정보 캐시 컬럼 추가
-- (매번 JOIN 하지 않도록 마지막 메시지 미리보기 저장)
ALTER TABLE chat_rooms
ADD COLUMN IF NOT EXISTS last_message_preview TEXT,
ADD COLUMN IF NOT EXISTS last_message_type TEXT DEFAULT 'text';

-- 2) chat_messages에 reply_to 지원 (선택적 인용 답장)
ALTER TABLE chat_messages
ADD COLUMN IF NOT EXISTS reply_to_id UUID REFERENCES chat_messages(id) ON DELETE SET NULL;

-- 3) 채팅 알림 테이블 (와글와글의 wagle_notifications와 별도)
CREATE TABLE IF NOT EXISTS chat_notifications (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id UUID NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE,
  room_id UUID NOT NULL REFERENCES chat_rooms(id) ON DELETE CASCADE,
  message_id UUID REFERENCES chat_messages(id) ON DELETE CASCADE,
  sender_id UUID NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE,
  type TEXT NOT NULL DEFAULT 'message' CHECK (type IN ('message', 'file', 'system')),
  preview TEXT,
  is_read BOOLEAN DEFAULT FALSE,
  created_at TIMESTAMPTZ DEFAULT NOW()
);

CREATE INDEX IF NOT EXISTS idx_chat_notifications_user_unread
ON chat_notifications(user_id, is_read, created_at DESC);

-- 4) chat_notifications RLS
ALTER TABLE chat_notifications ENABLE ROW LEVEL SECURITY;

CREATE POLICY "chat_notifications_select_own"
ON chat_notifications FOR SELECT
USING (auth.uid() = user_id);

CREATE POLICY "chat_notifications_update_own"
ON chat_notifications FOR UPDATE
USING (auth.uid() = user_id);

CREATE POLICY "chat_notifications_insert_participants"
ON chat_notifications FOR INSERT
WITH CHECK (
  EXISTS (
    SELECT 1 FROM chat_participants
    WHERE room_id = chat_notifications.room_id
    AND user_id = auth.uid()
  )
);

-- 5) last_message_preview 자동 갱신 트리거
CREATE OR REPLACE FUNCTION update_room_last_message_preview()
RETURNS TRIGGER AS $$
BEGIN
  UPDATE chat_rooms
  SET
    last_message_preview = CASE
      WHEN NEW.message_type = 'file' THEN '[파일] ' || COALESCE(NEW.file_name, '첨부파일')
      WHEN NEW.message_type = 'system' THEN NEW.content
      ELSE LEFT(NEW.content, 100)
    END,
    last_message_type = NEW.message_type
  WHERE id = NEW.room_id;
  RETURN NEW;
END;
$$ LANGUAGE plpgsql SECURITY DEFINER;

DROP TRIGGER IF EXISTS trigger_update_room_preview ON chat_messages;
CREATE TRIGGER trigger_update_room_preview
AFTER INSERT ON chat_messages
FOR EACH ROW
EXECUTE FUNCTION update_room_last_message_preview();

-- 6) 알림 자동 생성 트리거
CREATE OR REPLACE FUNCTION create_chat_notification()
RETURNS TRIGGER AS $$
BEGIN
  -- 상대방에게만 알림 생성 (본인 제외)
  INSERT INTO chat_notifications (user_id, room_id, message_id, sender_id, type, preview)
  SELECT
    cp.user_id,
    NEW.room_id,
    NEW.id,
    NEW.sender_id,
    NEW.message_type,
    CASE
      WHEN NEW.message_type = 'file' THEN '[파일] ' || COALESCE(NEW.file_name, '첨부파일')
      ELSE LEFT(NEW.content, 50)
    END
  FROM chat_participants cp
  WHERE cp.room_id = NEW.room_id
    AND cp.user_id != NEW.sender_id;

  RETURN NEW;
END;
$$ LANGUAGE plpgsql SECURITY DEFINER;

DROP TRIGGER IF EXISTS trigger_create_chat_notification ON chat_messages;
CREATE TRIGGER trigger_create_chat_notification
AFTER INSERT ON chat_messages
FOR EACH ROW
EXECUTE FUNCTION create_chat_notification();

-- 7) Realtime에 chat_notifications 추가
ALTER PUBLICATION supabase_realtime ADD TABLE chat_notifications;

-- 8) chat-files 스토리지 버킷 (이미 존재하면 무시)
-- Supabase 대시보드에서 확인: Storage > chat-files 버킷 존재 여부
-- 없으면 대시보드에서 생성:
--   Name: chat-files
--   Public: false
--   File size limit: 20MB
--   Allowed MIME types: */*
```

## 7. 주요 기술 결정 사항

### 7.1 패널 vs 모달

| 항목 | 결정 |
|------|------|
| 데스크톱 | 와글와글과 동일한 **사이드 패널** 방식 (모달 아님) |
| 모바일 | **전체화면 페이지** (/chat/:roomId) |
| 패널 크기 | 420px 너비 (와글와글과 동일) |
| 위치 | right: 128px (사이드바 버튼 왼쪽) |
| 애니메이션 | framer-motion spring (와글와글과 동일) |

### 7.2 채팅방과 와글와글의 독립성

```
와글와글 패널 (MessagesSquare)   채팅 패널 (MessageCircle)
  - 독립된 아이콘               - 독립된 아이콘
  - 독립된 스토어               - 독립된 스토어
  - 독립된 패널                 - 독립된 패널
  - 독립된 realtime 채널        - 독립된 realtime 채널
  - 공개 커뮤니티               - 비공개 1:1
```

### 7.3 파일 업로드 정책

- 저장소: Supabase Storage `chat-files` 버킷
- 경로: `{room_id}/{message_id}/{file_name}`
- 제한: 20MB, 모든 MIME 타입
- RLS: 채팅 참여자만 읽기/쓰기

### 7.4 메시지 페이지네이션

- 방식: 오프셋 기반 (레거시와 동일, 50개/페이지)
- 위로 스크롤 시 이전 메시지 로드
- 최신 메시지는 하단 고정 (auto-scroll)

### 7.5 읽음 처리

- 채팅방 진입 시 자동 `mark_room_as_read()` 호출
- Realtime으로 `unread_count` 갱신
- 배지에 실시간 반영

## 9. 레거시 대비 개선 사항 요약

| 문제 | 레거시 | 개선안 |
|------|--------|--------|
| 페이지 전환 | `window.location.href` (전체 리로드) | React Router SPA 내비게이션 |
| 프로필 조회 | N+1 개별 조회 | `getProfileInfoBatch()` 일괄 조회 + 캐시 |
| 컴포넌트 중복 | MessageBubble Desktop/Mobile 각각 정의 | `ChatMessageBubble` 공유 컴포넌트 |
| 탭 전환 버그 | visibilitychange에서 전체 리로드 시도 | delta fetch (마지막 timestamp 이후만) |
| 중복 채팅방 | 런타임에 중복 발생 | DB UNIQUE 제약 + get_or_create RPC 재활용 |
| admin API | 클라이언트에서 admin.getUserById() 호출 | user_profiles 테이블 직접 조회 |
| 알림 없음 | unread_count만 존재 | chat_notifications 테이블 + 트리거 자동 생성 |
