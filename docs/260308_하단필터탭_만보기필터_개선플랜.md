# 하단 필터탭 "만 보기" + 캐스케이딩 필터 연동 개선 플랜

> 작성일: 2026-03-08

## 1. 현재 문제

### 핵심 버그: 레이어 토글 활성 시 캐스케이딩 필터가 완전 무시됨

`Hero.tsx:711-717`의 로직:

```typescript
const anyLayerToggleActive = showJobLayer || showSeekerLayer || showInstructorLayer;

// 캐스케이딩 필터 적용 (레이어 토글 비활성 상태에서만)
if (cascadingFilter.primary && !anyLayerToggleActive) {
  filtered = filtered.filter(job => matchesCascadingFilter(job, cascadingFilter));
}
```

**"공고만 보기"를 누르면 `showJobLayer=true`가 되어 `anyLayerToggleActive=true` → 캐스케이딩 필터(특수, 교과과목 등) 적용 코드를 완전히 건너뜀.**

### 사용자 시나리오별 기대 vs 현실

| 조작 순서 | 사용자 기대 | 현재 동작 |
|-----------|------------|-----------|
| 공고만 보기 → 특수 | 특수 공고만 표시 | 모든 공고 표시 (필터 무시) |
| 공고만 보기 → 교과과목 → 영어 | 영어 교과 공고만 | 모든 공고 표시 (필터 무시) |
| 구직자만 보기 → 특수 | 특수 구직자만 | 구직자는 표시되나 필터 미적용 (별도 이슈) |
| 교원연수강사만 보기 → 에듀테크/AI | 해당 분야 강사만 | 강사 표시되나 필터 미적용 (별도 이슈) |
| (토글 없음) → 특수 | 특수 공고만 | 정상 작동 |

### 왜 이렇게 구현되었나 (추정)

레이어 토글과 캐스케이딩 필터가 **서로 다른 시기에 독립적으로 구현**된 것으로 보임.
- 캐스케이딩 필터: 공고(job_postings) 전용 필터로 설계됨
- 레이어 토글: 공고/구직자/강사 레이어 가시성 제어용으로 별도 추가

레이어 토글이 ON되면 "이 레이어만 보겠다"는 의미이므로, 필터는 별도로 적용할 필요가 없다고 판단한 듯.
실제로는 **"이 레이어만 보되, 그 안에서 세부 필터도 적용"**이 자연스러운 사용자 기대.

## 3. 수정 방안

### 핵심 수정: `anyLayerToggleActive` 조건 제거

**Before:**
```typescript
if (cascadingFilter.primary && !anyLayerToggleActive) {
  filtered = filtered.filter(job => matchesCascadingFilter(job, cascadingFilter));
}
```

**After:**
```typescript
if (cascadingFilter.primary) {
  filtered = filtered.filter(job => matchesCascadingFilter(job, cascadingFilter));
}
```

레이어 토글은 공고/구직자/강사 마커의 **표시 여부**를 제어하고 (이미 `unifiedItems` useMemo에서 `shouldShowJobs` 등으로 처리됨), 캐스케이딩 필터는 공고 목록의 **내용 필터링**을 담당. 두 기능은 독립적으로 동작해야 함.

### 검증 필요 사항

1. **레이어 토글 없이 필터만 사용** → 기존과 동일하게 작동하는지
2. **공고만 보기 + 특수** → 특수 공고만 표시되는지
3. **공고만 보기 + 교과과목 → 영어** → 영어 교과 공고만 표시되는지
4. **구직자만 보기** (필터 없음) → 구직자만 정상 표시되는지
5. **모든 토글 OFF + 필터 OFF** → 전체 목록 정상 표시

### 주의: 구직자/강사에 대한 캐스케이딩 필터 적용은 별도 이슈

현재 캐스케이딩 필터(`matchesCascadingFilter`)는 `job_postings` 구조에 맞춰 설계됨.
구직자(`teacher_markers`)나 강사(`instructor_markers`)에 동일 필터를 적용하려면 각각의 데이터 구조에 맞는 매칭 로직이 필요.
이는 서비스 규모가 커진 후 별도 작업으로 진행.

## 4. 부수 영향

### `activeLayers` 동기화 로직 (`Hero.tsx:508-537`)

레이어 토글이 `activeLayers` 배열도 제어하고 있음. 이 부분은 마커 렌더링 제어용이므로 `filteredJobPostings` 수정과 독립적. 영향 없음.

### 자동 스케일업 (`useAutoScaleMap`)

`filteredJobPostings.length`를 기반으로 동작. 수정 후 필터가 제대로 적용되면 결과 수가 줄어들어 자동 스케일업이 더 적절하게 발동될 수 있음. 긍정적 부수효과.

### 목록 카운트 표시

`filteredJobPostings.length`가 목록 카운트에 반영됨. 수정 후 "공고만 보기 + 특수" 시 카운트가 전체 598이 아니라 실제 특수 공고 수로 정확하게 표시됨.
