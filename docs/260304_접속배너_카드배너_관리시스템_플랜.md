### 1-3. 현재 접속시 팝업/모달 체계

| 모달 | 트리거 조건 | 제어 방식 |
|------|-------------|-----------|

| 약관 동의 모달 | OAuth 첫 로그인 | `sessionStorage` + DB |

### 3-3. 닫기 정책 동작 상세

| 정책 | localStorage 키 | 저장값 | 다시 표시 조건 |
|------|-----------------|--------|----------------|
| `once` (확인 후 다시 안뜸) | `popup_dismissed_{bannerId}` | `"forever"` | 배너 ID가 바뀌면 표시 |
| `7days` (7일간 안보기) | `popup_dismissed_{bannerId}` | ISO 날짜 문자열 | 7일 경과 후 |
| `1day` (오늘 하루 안보기) | `popup_dismissed_{bannerId}` | ISO 날짜 문자열 | 다음 날 |
| `always` (매번 표시) | 저장 안 함 | — | 항상 |

**dismiss 체크 로직 (프론트엔드)**:
```
function shouldShowPopup(banner):
    if banner.dismissPolicy === 'always': return true

    stored = localStorage.get(`popup_dismissed_${banner.id}`)
    if !stored: return true

    if stored === 'forever': return false

    dismissDate = parseDate(stored)
    if banner.dismissPolicy === '7days':
        return daysSince(dismissDate) >= 7
    if banner.dismissPolicy === '1day':
        return !isSameDay(dismissDate, today)

    return true
```

**표시 우선순위**:
- `popup_banner_config.is_active === true` AND
- `popup_banners` 중 `is_active === true`인 것 중 `display_order` 가장 낮은 1개만 표시
- dismiss 상태인 배너는 건너뛰고 다음 활성 배너를 표시
- 모든 활성 배너가 dismiss 상태면 팝업 안뜸

### 3-4. 접속배너 DB 스키마 (SQL 제안)

```sql
-- ============================================================
-- 접속배너 (Popup Banner) 테이블
-- ============================================================

-- 1. 전역 설정 테이블
CREATE TABLE IF NOT EXISTS public.popup_banner_config (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    is_active BOOLEAN DEFAULT false,                    -- 전체 활성화/비활성화
    dismiss_policy TEXT DEFAULT 'once'                   -- 'once' | '7days' | '1day' | 'always'
        CHECK (dismiss_policy IN ('once', '7days', '1day', 'always')),
    updated_by UUID REFERENCES auth.users(id),
    created_at TIMESTAMPTZ DEFAULT NOW(),
    updated_at TIMESTAMPTZ DEFAULT NOW()
);

-- 초기값 삽입
INSERT INTO public.popup_banner_config (is_active, dismiss_policy)
SELECT false, 'once'
WHERE NOT EXISTS (SELECT 1 FROM public.popup_banner_config);

-- 2. 배너 목록 테이블
CREATE TABLE IF NOT EXISTS public.popup_banners (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    title VARCHAR(100) NOT NULL,                        -- 제목 (필수)
    body TEXT,                                          -- 본문 (선택)
    image_url TEXT,                                     -- 이미지 URL (선택, Storage)
    link_url TEXT,                                      -- 클릭 시 이동 URL (선택)
    link_text VARCHAR(50) DEFAULT '자세히 보기',         -- 링크 버튼 텍스트
    bg_color VARCHAR(7) DEFAULT '#FFFFFF',              -- 배경색
    text_color VARCHAR(7) DEFAULT '#1F2937',            -- 텍스트색
    display_order INTEGER DEFAULT 0,                    -- 표시 우선순위 (낮을수록 먼저)
    is_active BOOLEAN DEFAULT true,                     -- 개별 활성화
    updated_by UUID REFERENCES auth.users(id),
    created_at TIMESTAMPTZ DEFAULT NOW(),
    updated_at TIMESTAMPTZ DEFAULT NOW()
);

-- 3. RLS 정책
ALTER TABLE public.popup_banner_config ENABLE ROW LEVEL SECURITY;
ALTER TABLE public.popup_banners ENABLE ROW LEVEL SECURITY;

-- 읽기: 모든 사용자
CREATE POLICY "popup_banner_config_read" ON public.popup_banner_config
    FOR SELECT USING (true);
CREATE POLICY "popup_banners_read" ON public.popup_banners
    FOR SELECT USING (true);

-- 쓰기: 인증된 사용자 (추후 admin role 체크로 강화)
CREATE POLICY "popup_banner_config_write" ON public.popup_banner_config
    FOR ALL USING (auth.role() = 'authenticated');
CREATE POLICY "popup_banners_write" ON public.popup_banners
    FOR ALL USING (auth.role() = 'authenticated');

-- 4. Storage 버킷 (popup-banners)
INSERT INTO storage.buckets (id, name, public)
VALUES ('popup-banners', 'popup-banners', true)
ON CONFLICT (id) DO NOTHING;

-- Storage 정책
CREATE POLICY "popup_banners_storage_read" ON storage.objects
    FOR SELECT USING (bucket_id = 'popup-banners');
CREATE POLICY "popup_banners_storage_insert" ON storage.objects
    FOR INSERT WITH CHECK (bucket_id = 'popup-banners' AND auth.role() = 'authenticated');
CREATE POLICY "popup_banners_storage_update" ON storage.objects
    FOR UPDATE USING (bucket_id = 'popup-banners' AND auth.role() = 'authenticated');
CREATE POLICY "popup_banners_storage_delete" ON storage.objects
    FOR DELETE USING (bucket_id = 'popup-banners' AND auth.role() = 'authenticated');
```

## 7. 디자인 원칙 (anti-vibe-design 기준)

> 참조: `.claude/skills/anti-vibe-design/SKILL.md`

### 절대규칙 체크리스트 (모든 배너 UI 공통)
```
[ ] 이모지 사용 안 함 (Rule 1)
[ ] 글자 뒤 배경색 사용 안 함 - 형광펜 금지 (Rule 2)
[ ] 프로젝트 컬러 팔레트만 사용 - 원색 지양 (Rule 3)
[ ] 컨셉 일관성: 파란색(#3B82F6) / 소프트레드(#F87171) / 회색 계열 (Rule 4)
[ ] 바이브코딩 냄새 금지 - 과한 그라디언트/그림자/애니메이션 없음 (Rule 5)
```

### 접속배너 팝업 디자인 원칙
1. **비침범적**: 콘텐츠 위 오버레이지만, 닫기 버튼 명확하고 크게
2. **한 눈에 읽힘**: 제목 `text-xl font-bold text-gray-800`, 본문 `text-sm text-gray-600`
3. **색상**: 기본 `bg-white` 배경 + `text-gray-800` 텍스트 (관리자가 변경 가능하되 기본값은 무채색)
4. **모달 구조**: 표준 모달 패턴 적용
   ```tsx
   // 오버레이
   "fixed inset-0 z-50 flex items-center justify-center bg-black/50"
   // 모달 본체
   "relative bg-white rounded-xl shadow-xl border border-gray-200 p-6 max-w-[420px] mx-4"
   // 닫기 버튼 영역
   "space-y-3" → Primary: "bg-[#3B82F6] text-white" / Secondary: "bg-gray-100 text-gray-600"
   ```
5. **모바일**: `max-w-[420px] mx-4` → 화면 80% 이하 차지, 스크롤 불필요
6. **닫기 옵션**: "닫기" + "N일간 안보기" 두 버튼 하단 배치
7. **로딩 차단 금지**: 팝업 fetch가 메인 콘텐츠 렌더링을 차단하지 않음 (비동기)
8. **이미지 처리**: `rounded-lg overflow-hidden`, `object-cover`, `max-h-[300px]`

### 카드배너 디자인 원칙
1. **카드와 조화**: `bg-white rounded-lg border border-gray-200` — 공고카드와 동일 외형
2. **구분 가능**: 우하단 `text-[10px] text-gray-400` "광고" 라벨
3. **높이 제한**: 일반 카드보다 낮은 높이 (이미지 비율 16:3 ~ 16:4)
4. **그림자**: `shadow-sm` (과하지 않게)
5. **호버**: `hover:shadow-md transition-all cursor-pointer`
6. **과다 노출 방지**: 삽입 간격 최소 3 이상 권장
7. **빈 상태**: 활성 배너 없으면 삽입 없이 일반 카드만 표시

### 관리자 UI 디자인 원칙
1. **기존 패턴 답습**: HeroBannerManager의 아코디언 + 폼 + 미리보기 패턴 유지
2. **즉시 피드백**: 저장 성공/실패 Toast (`toastStore` 사용)
3. **실시간 미리보기**: 입력값 변경 시 미리보기 즉시 반영
4. **위험 동작 확인**: 삭제 시 confirm 대화상자
5. **입력 필드**: `w-full px-3 py-2 bg-white border border-gray-200 rounded-lg focus:ring-2 focus:ring-blue-500`
6. **토글 버튼**: 활성 `bg-green-100 text-green-700` / 비활성 `bg-gray-100 text-gray-500`
7. **색상 선택**: `ColorInputField` 컴포넌트 재활용 (기존 것)

## 8. 사용자에게 실행 요청할 SQL

아래 SQL은 Phase 1 시작 전 Supabase SQL Editor에서 실행 필요:

```sql
-- ============================================================
-- [실행 요청] 접속배너 테이블 생성
-- ============================================================

-- 1. popup_banner_config 테이블
CREATE TABLE IF NOT EXISTS public.popup_banner_config (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    is_active BOOLEAN DEFAULT false,
    dismiss_policy TEXT DEFAULT 'once'
        CHECK (dismiss_policy IN ('once', '7days', '1day', 'always')),
    updated_by UUID REFERENCES auth.users(id),
    created_at TIMESTAMPTZ DEFAULT NOW(),
    updated_at TIMESTAMPTZ DEFAULT NOW()
);

INSERT INTO public.popup_banner_config (is_active, dismiss_policy)
SELECT false, 'once'
WHERE NOT EXISTS (SELECT 1 FROM public.popup_banner_config);

-- 2. popup_banners 테이블
CREATE TABLE IF NOT EXISTS public.popup_banners (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    title VARCHAR(100) NOT NULL,
    body TEXT,
    image_url TEXT,
    link_url TEXT,
    link_text VARCHAR(50) DEFAULT '자세히 보기',
    bg_color VARCHAR(7) DEFAULT '#FFFFFF',
    text_color VARCHAR(7) DEFAULT '#1F2937',
    display_order INTEGER DEFAULT 0,
    is_active BOOLEAN DEFAULT true,
    updated_by UUID REFERENCES auth.users(id),
    created_at TIMESTAMPTZ DEFAULT NOW(),
    updated_at TIMESTAMPTZ DEFAULT NOW()
);

-- 3. RLS
ALTER TABLE public.popup_banner_config ENABLE ROW LEVEL SECURITY;
ALTER TABLE public.popup_banners ENABLE ROW LEVEL SECURITY;

CREATE POLICY "popup_banner_config_read" ON public.popup_banner_config FOR SELECT USING (true);
CREATE POLICY "popup_banners_read" ON public.popup_banners FOR SELECT USING (true);
CREATE POLICY "popup_banner_config_write" ON public.popup_banner_config FOR ALL USING (auth.role() = 'authenticated');
CREATE POLICY "popup_banners_write" ON public.popup_banners FOR ALL USING (auth.role() = 'authenticated');

-- 4. Storage 버킷
INSERT INTO storage.buckets (id, name, public)
VALUES ('popup-banners', 'popup-banners', true)
ON CONFLICT (id) DO NOTHING;

CREATE POLICY "popup_banners_storage_read" ON storage.objects FOR SELECT USING (bucket_id = 'popup-banners');
CREATE POLICY "popup_banners_storage_insert" ON storage.objects FOR INSERT WITH CHECK (bucket_id = 'popup-banners' AND auth.role() = 'authenticated');
CREATE POLICY "popup_banners_storage_update" ON storage.objects FOR UPDATE USING (bucket_id = 'popup-banners' AND auth.role() = 'authenticated');
CREATE POLICY "popup_banners_storage_delete" ON storage.objects FOR DELETE USING (bucket_id = 'popup-banners' AND auth.role() = 'authenticated');
```

## 9. 의존성 및 리스크

| 리스크 | 대응 |
|--------|------|
| localStorage 초기화 시 팝업 재표시 | 의도된 동작 (시크릿 모드에서도 표시) |
| 이미지 없이 텍스트만 배너 | UI에서 이미지 없을 때도 자연스러운 레이아웃 |
| 모바일에서 팝업 + PWA 설치 모달 겹침 | PWA 설치 → 약관 → 접속배너 순서로 우선순위 관리 |
| 카드배너 이미지 비율 불일치 | 관리자 UI에서 권장 비율 안내 + object-cover 처리 |
| 띠지배너 삭제 시 기존 데이터 | DB 테이블은 유지하되 프론트 코드만 삭제 (Phase 3) |
