# 울산/서울/인천 크롤링 오류 개선플랜

> 작성일: 2026-03-04
> 상태: **로그 확인 완료, 수정 대기**

## 1. 현상

관리콘솔에서 3개 게시판이 "실패"로 표시됨:
- 울산광역시교육청 인력풀 — `수집된 공고 없음 - HTML 구조 변경 의심`
- 서울교육청 교육행정직 채용 — `수집된 공고 없음 - HTML 구조 변경 의심`
- 인천교육청 교육행정직 채용 — `수집된 공고 없음 - HTML 구조 변경 의심`

GitHub Actions에서는 3개 모두 녹색 체크(성공)로 표시됨.

## 2. 원인 분석

### 왜 GitHub Actions는 성공인데 관리콘솔은 실패인가?

`crawler/index.js:534-537`:
```javascript
if (rawJobs.length === 0) {
  await recordCrawlFailure(crawlSourceId, '수집된 공고 없음 - HTML 구조 변경 의심');
  process.exit(0);  // ← exit code 0 = GitHub Actions "성공"
}
```

- `process.exit(0)` → GitHub Actions는 종료코드 0 = 성공으로 인식
- `recordCrawlFailure()` → `crawl_logs` 테이블에 `status: 'failed'` 기록
- 관리콘솔은 `crawl_logs`를 참조하므로 실패로 표시

**두 시스템이 서로 다른 데이터 소스를 보고 있어서 불일치가 발생.**

---

### 2-1. 울산광역시교육청 인력풀 (`ulsan`) — 오탐(False Positive)

**확정된 사실 (GitHub Actions 로그에서 확인):**

```
📊 발견된 공고 수: 10개
⚠️ 연속 중복 10개 도달 - 크롤링 종료
✅ [울산] 울산광역시교육청 인력풀 크롤링 완료
   - 신규: 0개
   - 중복 스킵: 10개
[WARN][crawler] 수집된 공고 없음, HTML 구조 변경 의심
❌ 크롤링 실패 기록 완료
```

**흐름:**
1. 울산 크롤러가 페이지에서 10개 공고를 정상 파싱
2. 10개 모두 DB에 이미 존재 (중복)
3. `crawlUlsan()` 함수가 신규 항목만 반환 → `jobs = []` (0개)
4. `index.js:534`에서 `rawJobs.length === 0` 확인 → **실패로 기록**

**진짜 원인: 울산 크롤러(`crawler/sources/ulsan.js`)가 내부에서 중복 체크를 수행하고, 신규 항목만 반환하는 구조.**
다른 크롤러들은 전체 목록을 반환하고 `index.js` 파이프라인에서 중복 처리하는데,
울산만 크롤러 내부에서 처리 후 신규만 반환함.

**결론: HTML 구조 변경이 아님. 페이지 파싱 정상. 단순히 새 공고가 없었을 뿐.**

**흐름:**

3. 10개 모두 DB에 이미 존재 → 전부 스킵 (중복 100%)

**진짜 원인: 울산과 동일한 패턴.** NTT 범용 크롤러도 내부에서 중복 체크 후 신규만 반환하는 구조.
페이지 파싱은 완벽하게 동작했고, 단순히 새 공고가 없었을 뿐.

**결론: HTML 구조 변경이 아님. NTT 파싱 정상. 전부 기존 중복이라 신규 0건 → 오탐.**

## 4. 수정 계획

### 4-1. [확정] 울산 오탐 수정 — `index.js:534` 실패 판정 로직 개선

**문제:** `rawJobs.length === 0`이면 무조건 실패로 기록하지만,
"페이지에서 아무것도 못 파싱" vs "파싱은 됐는데 전부 중복"은 다른 상황.

**수정 방안:**

울산 크롤러(`sources/ulsan.js`)가 반환 시 메타 정보를 포함하도록 변경:

```javascript
// ulsan.js: 기존
return jobs;  // 신규만

// ulsan.js: 변경안
return { jobs, meta: { totalFound: jobListData.length, skipped: skippedCount } };
```

`index.js`에서 메타 정보를 활용:

```javascript
// index.js:534 부근
if (rawJobs.length === 0) {
  // 울산처럼 크롤러가 내부 중복처리를 하는 경우 구분
  if (crawlMeta && crawlMeta.totalFound > 0) {
    // 페이지에서 공고는 발견했지만 전부 중복 → 성공으로 처리
    logStep('crawler', '신규 공고 없음 (전부 기존 중복)', {
      totalFound: crawlMeta.totalFound,
      skipped: crawlMeta.skipped
    });
    await updateCrawlSuccess(crawlSourceId, {
      jobsFound: crawlMeta.totalFound,
      jobsSaved: 0,
      jobsSkipped: crawlMeta.skipped
    });
    process.exit(0);
  }

  // 페이지에서 아무것도 파싱 못한 경우 → 진짜 실패
  logWarn('crawler', '수집된 공고 없음, HTML 구조 변경 의심', { targetSource });
  await recordCrawlFailure(crawlSourceId, '수집된 공고 없음 - HTML 구조 변경 의심');
  process.exit(1);  // exit(1)로 변경하여 GitHub Actions에서도 실패로 표시
}
```

**추가:** `process.exit(0)` → `process.exit(1)` 변경하여 GitHub Actions와 관리콘솔 상태 일치시키기.

### 4-2. [확정] seoul-admin 오탐 수정 — 울산과 동일한 패턴

**로그 확인 결과:** NTT 크롤러가 정상 동작. 10개 파싱 후 전부 중복 → 신규 0건 → 오탐.

**수정:** 4-1의 `index.js:534` 실패 판정 로직 개선으로 함께 해결됨.
NTT 크롤러도 울산과 마찬가지로 내부 중복 체크 후 신규만 반환하므로,
`crawlMeta` 반환 구조를 NTT 크롤러에도 적용하면 오탐이 사라짐.

### 4-3. [확정] incheon-admin 진짜 실패 — URL 비정상

**로그 확인 결과:** 페이지가 `about:blank`로 로드. contentLength=0, tableCount=0.

**원인:** `https://www.ice.go.kr/user/bbs/BD_selectBbsList.do?q_bbsCode=1046&q_clCode=2&bbsAllTy=exam`
이 URL이 빈 페이지를 반환함. 인천교육청 사이트가 `bbsAllTy=exam` 파라미터를 지원하지 않거나 차단.

**수정 방안:**
1. 먼저 브라우저에서 해당 URL 직접 접속하여 현재 상태 확인
2. **가능성 A**: URL 파라미터 변경 (`bbsAllTy` 제거 또는 다른 값)
3. **가능성 B**: 인천교육청이 교육행정직 채용을 별도 URL로 이동 → `sources.json`의 `baseUrl` 업데이트
4. **가능성 C**: 해당 게시판이 폐지됨 → `crawl_boards`에서 비활성화 및 매트릭스에서 제거

### 4-4. [선택] GitHub Actions exit code 정합성 개선

현재 크롤링 실패를 `process.exit(0)`으로 종료하여 GitHub Actions에서는 성공으로 표시됨.
실제 실패 시 `process.exit(1)`로 변경하면 GitHub Actions에서도 실패로 표시되어 모니터링 정합성 향상.

```javascript
// 변경: exit(0) → exit(1) (실패 시)
await recordCrawlFailure(crawlSourceId, '수집된 공고 없음 - HTML 구조 변경 의심');
process.exit(1);  // GitHub Actions에서도 실패로 표시
```

⚠️ **주의:** `fail-fast: false` 설정이 워크플로우에 있으므로, 하나가 실패해도 다른 크롤러는 계속 실행됨. exit(1) 변경 안전.
